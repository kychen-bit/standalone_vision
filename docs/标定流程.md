# 标定流程（从装好相机到能上场）

## 最短路径（只想把颜色跑稳，就做这三件）

1. **曝光**：把 `illumination.exposure_hint` 调到 `OK`（gain 0.9~1.3）；
2. **判色**：鼠标指物料，按 `1`~`6`，再按 `w` 存原型（做一次就够，换灯/换场地不用重做）；
3. **面积与形状**：在窗口里按 `d` 看诊断，把 `recommended_area` 的 `min_area/max_area`
   写进 `scenes.TURNTABLE`（默认 700/500000 等于没有面积过滤）；
4. **视场**：上下不够就切 `--capture-profile wide_4_3`，够就别动。

```bash
sudo systemctl stop standalone-vision.service
python3 tools/test_turntable_color_live.py --task-code 234+123+432+231 --batch 1 --target 3
# 窗口里：d=诊断 1~6=按色号采原型 w=存盘 q=退出
```

下面的分节是遇到具体问题再查的手册，不需要一次全做完。
**有补光时**（`lighting.fill_light: true`）连第 2 步都不用做：白场归一化会自动关闭，
你之前标定的 HSV 阈值照旧生效。

---

按顺序做时，**每一步的产出都是下一步的输入**，跳过会返工。所有命令在项目根目录执行。

## 0. 先理解三条依赖关系

| 改动 | 需要重做 |
|---|---|
| 相机高度 / 俯仰角 / 镜头焦距 | 全部（ROI、颜色、圆环模板、平面单应） |
| 采集模式（分辨率/裁切） | 全部（同上，本质是改了视场） |
| 相机位置或场地位置微动 | 场景 ROI + 平面单应（颜色原型不用重采） |
| 换灯 / 换场地光照 | 只需看 `gain` 是否仍 OK；原型与阈值都不用动 |
| 换同一批物料 | 一般不用动；色差大时重新标颜色原型 |

**视野由"镜头焦距 + 相机到工作面的距离"决定，与分辨率无关。** 固定高度后软件只能裁切变窄
（`zoom_absolute` 0~60 = 1.0×~2.0×），唯一不改硬件还能变宽的是切 4:3 模式（上下 +33%，见
[环境光鲁棒色块识别](环境光鲁棒色块识别.md) 8.1）。想左右更宽只能换短焦镜头或把相机挪远。

每个阶段开始前停掉后台服务，避免相机被占用：

```bash
sudo systemctl stop standalone-vision.service
```

---

## 1. 机械与光学定死

1. 固定相机支架（高度、俯仰、到工作面的距离），把螺丝拧到不会再动。
2. 装上真正要用的镜头（判定视场是否够，见第 4 步的量法；不够就现在换短焦镜头）。
3. **手动对焦**到最常用的工作面（转盘面），锁死 `focus_automatic_continuous=0`。
   对焦判据：把一只物料或一张小字纸放在转盘面上，画面最锐即可。
4. 决定补光方案，写进配置：

```json
"lighting": { "fill_light": false }     // false=无补光（本届规则），true=有补光
```

5. 记录：镜头焦距、安装高度、到转盘面的距离、光方案。后面所有数字都要跟这份记录绑定。

---

## 2. 采集模式与帧率

当前默认 `1280×720@60`（16:9 上下裁切）。若需要上下多看 33%：

```json
"camera": { "width": 1280, "height": 960, "fps": 50 }
```

- `1280×960` 最高 **50 fps**，写 60 会导致 gstreamer 协商失败并静默回退 `opencv_v4l2`；
- 改了尺寸后，第 5 步的 ROI 和第 7 步的圆环模板都要按新尺寸重做；
- 验收：启动日志里出现 `CAMERA_READY`，且没有 `CAMERA_BACKEND_WARNING`。

```bash
python3 -m jetson_recognition.run live --mode COLOR --scene TURNTABLE --target red --show-fps
```

---

## 3. 曝光与白平衡（把 gain 收进 0.9~1.3）

先关自动，只手动调曝光，让白场落在 200~240。**判据是诊断里的 `gain` 与 `exposure_hint`**：

```bash
python3 tools/test_turntable_color_live.py --task-code 234+123+432+231 --batch 1 --target 3
# 看输出里的 illumination：{"gain": [...], "exposure_hint": "...", "clipped_ratio": ...}
```

| `exposure_hint` | 动作 |
|---|---|
| `RAISE_EXPOSURE` | 加 `exposure_time_absolute`（或补光），gain 到 0.9~1.3 |
| `OK` | 通过 |
| `LOWER_EXPOSURE` / `WHITE_FIELD_CLIPPED` | 减曝光，削顶无法恢复 |

调好后把参数存进活动档（`competition_locked`，注意该档 `_replace_base: true`，
顶层 `camera.v4l2_controls` 不生效）：

```bash
python3 tools/capture_camera_profile.py --profile competition_locked \
  --settle-seconds 10 --stable-seconds 3 --timeout-seconds 45 --activate
```

自动流程回读异常时改用手动步骤（见 [赛前颜色调参指南](赛前颜色调参指南.md) 第 3 节），
最后用 `v4l2-ctl --get-ctrl=...` 回读确认，并把数值写进 `competition_locked`。

**验收**：重启程序后 `exposure_hint=OK`；人为遮一半环境光再放开，`gain` 能回到 OK。

---

## 4. 量一下自己的视野（可选，但强烈建议）

知道 1 像素等于多少毫米，后面所有 `min_area`、`stable_spread_px` 才有物理意义。
把已知长度的物体（例如转盘的 φ300 外圆、或一条 300 mm 的尺）摆在工作面上：

```bash
python3 tools/pick_roi.py --known-mm 300
```

鼠标沿该物体的长边拉框，回车，终端会输出：

```text
{"state":"ROI_PICKED","size_px":[1280,500],"mm_per_px":0.2344,"field_mm":[300.0,168.8]}
```

- `mm_per_px`：该平面上的像素当量（只对同一高度有效）；
- `field_mm`：当前整帧覆盖的实际范围 —— 这就是"你现在能看多大"的答案。

拿它对比需求（转盘 φ300、暂存区 580×150、二维码板 A4），判断视场够不够、
是否需要换镜头或改采集模式。

---

## 5. 场景 ROI

所有 ROI 都是**绝对像素坐标**，必须用刚定死的机位画。工具支持拾取 + 写回（自动备份）：

```bash
# 转盘场景（颜色识别用）
python3 tools/pick_roi.py --scene TURNTABLE --key object_roi    --write
python3 tools/pick_roi.py --scene TURNTABLE --key turntable_roi --write

# 粗加工区（PLACE 用）
python3 tools/pick_roi.py --scene ROUGH --key ring_search_roi --write
python3 tools/pick_roi.py --scene ROUGH --key ring_rois.1 --write
python3 tools/pick_roi.py --scene ROUGH --key ring_rois.2 --write
python3 tools/pick_roi.py --scene ROUGH --key ring_rois.3 --write

# 暂存区（STACK 用；object_roi 要覆盖能同时看到三块物料的区域）
python3 tools/pick_roi.py --scene STORAGE --key object_roi      --write
python3 tools/pick_roi.py --scene STORAGE --key ring_rois.1 --write
python3 tools/pick_roi.py --scene STORAGE --key ring_rois.2 --write
python3 tools/pick_roi.py --scene STORAGE --key ring_rois.3 --write
```

操作：鼠标拖框 → `SPACE`/`ENTER` 确认 → `r` 重画 / `w` 写回 / `q` 放弃。
不想开 GUI 时先存一张图再量：

```bash
python3 -m jetson_recognition.run image frame.jpg --mode COLOR --scene TURNTABLE --target 1 --save marked.jpg
python3 tools/pick_roi.py --image frame.jpg --scene ROUGH --key ring_rois.2 --write
```

**画 ROI 的原则**

- `object_roi`：颜色搜索区，**要包含物料可能出现的全部位置**，并把边界留给
  `border_margin_px`（物料贴边会被判为不可信而丢弃）；
- `ring_rois`：仅在**关掉数字模板**（`ring_detection.digit_template.enabled=false`）时用于定位；
  默认开着模板走 `ring_search_roi` + 数字匹配。但它**仍然必须存在**：`detect_stack` 会校验
  环号是否配置过，缺了会直接报错，所以三个环的框都留着（尺寸按实际环位画）；
- `turntable_roi`：转盘外圆所在区域，与 `object_roi` 可以相同。

**验收**：

```bash
python3 -m jetson_recognition.run live --mode COLOR --scene TURNTABLE --target 1 --show-roi
python3 -m jetson_recognition.run live --mode RING  --scene ROUGH --target 1
```

第二行要能对 1/2/3 号环分别输出正确数字（`digit_score` 越高越好）。

## 6. 颜色标定（判色的准头就在这一步）

前提：第 3 步的 `exposure_hint=OK`。否则先回第 3 步，欠曝时标出来的原型不可信。

1. 把这一轮的三块真实物料按实际摆放放到转盘上（或工作面上）；
2. 跑批次工具：

```bash
python3 tools/test_turntable_color_live.py --task-code 234+123+432+231 --batch 1 --target 3
```

3. 鼠标依次指到每块物料上，按它对应的色号 `1`~`6`（终端回 `PROTOTYPE_LOCKED`），
   六种颜色都做完后按 `w` 写回（回 `PROTOTYPES_SAVED`，会先备份）；
4. 复查 `materials[]`：`distance` 应接近 0、`confidence` 接近 1、`assignment_gap` 明显大于 0；
5. 按实测值收紧形状与面积门限：

| 参数 | 怎么定 |
|---|---|
| `geometry.min_area` | 取物料实测面积的一半左右（工具里的 `area` 字段）；太小会放进噪声，太大会丢远处物料 |
| `geometry.max_area` | 取最大可能物料面积的 2 倍 |
| `geometry.min_mass_ratio` | 先看实物料的实测值（通常 0.85~1.0），取比它低 0.1~0.15 的值 |
| `geometry.max_aspect_ratio` | 物料最长/最宽比例 + 0.2 裕量 |
| `colors.*.hsv_ranges` | **两个方向都要查**（详见 6.1）：`v_min` 往**下**放开到物料亮度的约一半（不低于 60，别碰噪声地板）；`s_min` 往**上**收到"同色相背景的 S + 20~40"，否则台面会整片进掩码 |

6. **验收**：换暖光/冷光/遮光后重跑，`round_batch` 不变、`batch_stable=true`。

## 7. 圆环数字模板（PLACE/STACK 依赖）

内置的是字体模板，只在屏测下准。真实场地必须采一遍：

```bash
python3 tools/capture_ring_digit_templates.py     # 按提示对 1/2/3 环采集
python3 -m jetson_recognition.run live --mode RING --scene ROUGH --target 2
```

**验收**：三个环分别输出正确数字，`digit_score` 稳定（工具里会显示）。

## 8. 平面标定（可选，只影响单位 PX→MM）

不标定也能跑，输出 `unit=PX`，电控按像素用。要输出毫米才做：

- 每个平面单独标（转盘面、粗加工区面、暂存区面高度不同，单应矩阵不通用）；
- 相机高度或俯仰一变，全部重标；
- 标定结果写 `config/calibration.json`，每项的 `calibrated` 置 true 后 `unit` 才会变 `MM`。

**别指望它提升判色准确度**：颜色准不准由第 3、6 步决定。

## 9. 端到端验收（按顺序逐级）

```bash
# 1) 纯软件回归：不需要硬件
python3 tools/simulate_full_control_loop.py          # 看到 FULL_COMPETITION_SIMULATION_OK

# 2) 六色单点
python3 -m jetson_recognition.run live --mode COLOR --scene TURNTABLE --target 1   # 依次 1~6

# 3) 真 Maix + 真相机 + 模拟电控，跑完整两批六件
python3 tools/run_hardware_flow_test.py              # 看到 FULL_HARDWARE_FLOW_OK

# 4) 接真电控：coordinator
./run_competition.sh                                 # 先看 COORDINATOR_READY，再让电控发 START
```

每级的通过标志：

| 级别 | 通过标志 |
|---|---|
| 软件回归 | `FULL_COMPETITION_SIMULATION_OK`，`queue_index=6` |
| 批次颜色 | `round_batch` 正确且 `batch_stable=true` |
| 硬件流程 | `FULL_HARDWARE_FLOW_OK`，`vision_actions=24`、`stack_actions=3` |
| 整机 | 电控收到 `TASK_PLAN`→`GRASP_READY`→`DONE_ACK` 全程无 `ERROR` |

最后把服务恢复：

```bash
sudo systemctl start standalone-vision.service
```
