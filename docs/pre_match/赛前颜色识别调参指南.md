# Jetson 俯视六色识别赛前调参指南

适用对象：第一次在比赛现场调试相机和 HSV 的同学。  
适用流程：固定 ROI → HSV Mask → 轮廓 → 面积 → 中心点 → 连续 3 帧稳定。  
六种颜色：红、黄、蓝、绿、黑、浅蓝。

## 1. 第一原则：默认能识别，就不要调

先在最终相机位置、最终背景和最终补光下依次测试六种真实物料：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target red \
  --show-mask --show-fps
```

依次把 `red` 替换为：

```text
red  yellow  blue  green  black  light_blue
```

满足下面四条就直接保留现有参数：

- 目标放在工作区域的中央、四角、亮处和暗处都能识别；
- 目标 Mask 连续完整，背景大部分为黑色；
- 静止目标能快速进入 `STABLE`，移走后能进入 `LOST`；
- 相邻颜色不会互相误识别，尤其是蓝色和浅蓝色。

不要因为画面“看起来不够漂亮”而调参。识别稳定比肉眼观感重要。

只有出现漏识别、误识别、色温持续漂移、画面过暗/过曝、运动拖影或对焦反复变化时，才继续下面步骤。

## 2. 调参总顺序

严格按这个顺序进行：

```text
固定机械安装和补光
→ 固定曝光、白平衡、焦距、增益
→ 确认 ROI
→ 标定六色 HSV
→ 最后调整形态学和面积
→ 全场景复测
```

禁止同时调整相机参数和 HSV。相机画面仍在变化时测出的 HSV 很快会失效。

开始前先备份：

```bash
cp config/jetson.json config/jetson.pre_match.backup.json
```

## 3. 固定比赛现场条件

在锁定相机参数前完成：

1. 固定相机高度、俯视角度和工作距离；
2. 固定补光位置、方向和亮度；
3. 放好真实背景，并在画面内放入六种真实物料；
4. 避免补光直射产生大面积反光；
5. 后续不要再移动相机、镜头和灯。

补光优先保证“均匀”，不是越亮越好。过亮会导致浅色过曝，过暗会迫使曝光或增益升高，引入拖影和噪声。

## 4. 查看当前相机状态

启动一次识别，查看开头的 `CAMERA_READY`：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target red \
  --headless --show-fps --stats-every 60
```

也可以直接回读：

```bash
v4l2-ctl -d /dev/video0 \
  --get-ctrl=white_balance_automatic,white_balance_temperature,auto_exposure,exposure_time_absolute,gain,focus_automatic_continuous,focus_absolute
```

常用自动开关：

| 参数 | 自动状态 | 锁定状态 |
|---|---:|---:|
| `white_balance_automatic` | `1` | `0` |
| `auto_exposure` | `3` | `1` |
| `focus_automatic_continuous` | `1` | `0` |

自动状态适合寻找初始值，不适合比赛长期运行；大面积背景变化可能让曝光和色温继续漂移。

## 5. 推荐锁参方法：先自动收敛，再固定

保持最终画面不动，让自动曝光、白平衡和对焦观察 10 秒，然后保存并启用锁定档：

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --activate
```

成功时终端应出现：

```text
CAMERA_PROFILE_CAPTURED
```

并且 `verified_controls` 中应满足：

```text
white_balance_automatic = 0
auto_exposure = 1
focus_automatic_continuous = 0
```

这个命令不是凭经验猜参数，而是读取自动算法在当前真实画面下的收敛结果，再关闭三个自动开关。

锁定后重新启动识别，确认画面颜色、亮度和清晰度不再自行变化：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target red \
  --camera-profile competition_locked \
  --show-mask --show-fps
```

## 6. 自动结果不好时，怎样手动微调

每次只调整一个参数，修改后重新观察全部六色和背景。

### 6.1 曝光 `exposure_time_absolute`

- 数值增大：画面更亮，但运动拖影风险增加，可能影响实际帧率；
- 数值减小：画面更暗，但运动轮廓更清楚；
- 有过曝区域时先减曝光；整体太暗时优先增加补光，不要先大幅增加增益。

以自动收敛值为起点，每次小幅调整。下面的数字只是命令格式示例，应替换为现场测得值：

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --exposure 80 \
  --activate
```

### 6.2 白平衡 `white_balance_temperature`

- 使用白纸或中性灰卡判断，不要只盯着某一个彩色色块；
- 白纸明显偏蓝或偏黄时才调整；
- 每次调整约 `100～300`，观察白/灰是否恢复中性；
- 不同摄像头的视觉变化方向可能不同，以实际画面为准。

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --white-balance 4600 \
  --activate
```

### 6.3 焦距 `focus_absolute`

- 把带直线边缘或小文字的物体放在实际工作平面；
- 先记录自动对焦稳定后的值；
- 每次上下调整约 `5～10`，选择边缘最清楚的值；
- 相机高度固定后保持手动焦距，避免比赛时来回“拉风箱”。

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --focus 414 \
  --activate
```

### 6.4 增益 `gain`

- 光线足够时尽量保持较低值，通常从 `0` 开始；
- 增益升高会放大噪声，使 Mask 出现散点；
- 调整优先级：补光 → 曝光 → 增益。

可以一次覆盖多个已经确认的值：

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --white-balance 4600 \
  --exposure 80 \
  --focus 414 \
  --gain 0 \
  --activate
```

上述数字只演示写法，不是比赛推荐值。

## 7. 固定相机后标定六色 HSV

颜色参数位于：

```text
config/jetson.json → colors
```

每种颜色单独运行：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target light_blue \
  --camera-profile competition_locked \
  --show-mask --show-hsv
```

把鼠标移到物料内部，记录 `HSV05 / HSV50 / HSV95`。同一种物料至少测量：

- 中央、四角；
- 最亮处、最暗处；
- 静止和缓慢移动；
- 两到三个不同位置。

### 7.1 红、黄、绿、蓝、浅蓝

配置格式：

```json
"hsv_ranges": [
  {
    "h_min": 45,
    "h_max": 85,
    "s_min": 80,
    "s_max": 255,
    "v_min": 40,
    "v_max": 255
  }
]
```

简单确定方法：

1. 用多次测量的最低/最高 H 覆盖物料；
2. H 两边只留少量余量，通常先试 `3～5`；
3. `s_min` 略低于测得的最低 S，用于排除灰白背景；
4. `v_min` 略低于测得的最低 V，用于兼容较暗区域；
5. `s_max/v_max` 通常先保持 `255`；
6. 重启程序后观察 Mask，再做小幅修正。

红色跨越 OpenCV H 的首尾，允许保留两段范围：

```text
0～低端上限
高端下限～179
```

蓝色和浅蓝色先继续使用各自独立 HSV 范围，不要提前加入 Lab。

### 7.2 黑色

黑色不判断 H，第一版只调亮度 V：

```json
"black_threshold": {
  "v_max": 80,
  "s_min": 0,
  "s_max": 255
}
```

- 黑色物料漏掉：小幅提高 `v_max`；
- 阴影或深色背景被识别：降低 `v_max`；
- 每次修改约 `5～10`，同时检查有目标和无目标背景。

如果固定补光后仍无法区分黑色和阴影，再考虑未来的局部亮度对比；赛前不要临时堆复杂算法。

## 8. Mask、面积和形态学怎么判断

理想 Mask：目标主体为连续白色，背景基本为黑色，边缘允许有少量缺口。

先调 HSV，只有 HSV 基本正确后才调整：

- 零散小白点：先收紧 HSV；仍存在时把开运算次数从 `1` 调到 `2`；
- 目标内部小黑洞：把闭运算次数从 `1` 调到 `2`；
- 小噪声被画框：提高 `min_area`；
- 真实目标被面积拒绝：降低 `min_area`；
- 不要临时加入长宽比、圆度、多边形或复杂分类器。

每次修改 `config/jetson.json` 后都要退出并重新启动程序，配置不会在线自动刷新。

## 9. 最终验收清单

对每种颜色完成下面测试：

| 测试项 | 合格标准 |
|---|---|
| ROI 中央和四角 | 都能进入 `STABLE` |
| 最亮处和最暗处 | 无持续漏检 |
| 缓慢移动后停止 | 中心跟随，停止后稳定 |
| 移走目标 | 正确进入 `LOST` |
| 无目标背景 | 不持续产生稳定误框 |
| 其他五色 | 不被识别成当前颜色 |
| 帧率 | `capture_fps/fps` 满足现场需求 |

最后保存现场配置副本：

```bash
cp config/jetson.json config/jetson.competition.final.json
```

## 10. 现场快速故障判断

```text
六色都正常
→ 不调

所有颜色同时变差，原图也变色/变暗
→ 检查灯和相机锁参，不先改 HSV

只有一种颜色 Mask 全黑
→ 调该颜色 H/S/V

只有黑色异常
→ 调 black_threshold.v_max

Mask 正确但没有框
→ 检查 min_area/max_area

框正确但一直 UNSTABLE
→ 检查多个误轮廓、目标移动和 max_center_delta_px

capture_fps 低而 detect_ms 很小
→ 相机取流/解码问题，和 HSV、ROI 无关
```

## 11. 三条现场纪律

1. 默认能用就不调；
2. 一次只改一个参数，并记录修改前后的值；
3. 先稳定光学输入，再调整识别阈值。
