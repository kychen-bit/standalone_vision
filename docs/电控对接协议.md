# 电控与 Jetson 对接协议

本文是电控联调的唯一协议说明，依据当前实现
`jetson_recognition/protocol.py`、`jetson_recognition/coordinator.py` 和
`config/jetson.json` 整理。正式整车必须运行 `coordinator`；不要接入仅供单模块调试的
`VISION_RESULT`。

## 1. 对接结论

```text
MaixCAM Pro --USB虚拟网卡/TCP--> Jetson --全双工UART--> 电控
                     任务码                 本文协议
```

- 电控只与 Jetson 通信，不需要解析 MaixCAM 的 TCP 数据。
- Jetson 与电控之间为全双工串口：`115200 bit/s，8N1，无校验，无流控`。
- 电控负责导航、机械臂、夹爪、动作安全和超时恢复；Jetson 只负责识别和任务状态协调。
- `TURNTABLE` 已于 2026-09-20 完成毫米标定（`config/calibration.json`），该场景 `unit=MM`；`ROUGH`/`STORAGE` 仍未标定，保持 `PX`。拿到 `PX` 时不能把像素直接当毫米坐标。
- 每轮必须先完成 `START → READY → TASK_PLAN`，之后 Jetson 才接受 `REQ`。

## 2. 串口与数据帧

### 2.1 接线和串口参数

| 项目 | 要求 |
|---|---|
| 物理链路 | Jetson 串口或 Jetson 上的 USB-TTL 与电控 UART，全双工 |
| 接线 | `Jetson TX → 电控 RX`、`Jetson RX ← 电控 TX`、`GND ↔ GND` |
| 电平 | 使用 3.3 V TTL；禁止接 RS-232 电平，禁止把 5 V TTL 直接接 Jetson GPIO |
| 波特率 | `115200`，由 `coordinator.baud` 配置 |
| 数据格式 | 8 数据位、1 停止位、无校验、无硬件/软件流控 |
| Jetson 设备 | `coordinator.mcu_serial`，建议使用 `/dev/serial/by-id/...` 稳定路径 |
| 收发缓存 | 建议至少 256 字节；Jetson 发出的正文最长 176 字节 |

若使用 USB-TTL，只连接 `TX/RX/GND`；两块控制板按各自设计供电，不要默认用串口模块的 VCC
互相供电。

### 2.2 帧格式

```text
@NAME,FIELD1,FIELD2,...*CCCC\n
```

| 部分 | 说明 |
|---|---|
| `@` | 一帧起始符，不参与 CRC |
| `NAME,FIELD...` | ASCII 正文，参与 CRC；字段用英文逗号分隔 |
| `*` | CRC 分隔符，不参与 CRC |
| `CCCC` | 4 位十六进制 CRC，Jetson 使用大写输出 |
| `\n` | 帧结束符 LF，即 `0x0A`，不参与 CRC |

字段必须非空，建议只使用 ASCII 字母、数字、下划线、点和正负号；字段内禁止 `,`、`*`、`@`、
CR、LF。发送时不要插入空格。帧名不区分大小写，但统一发送大写。

CRC 参数：

| 参数 | 值 |
|---|---:|
| 算法 | CRC-16/CCITT-FALSE |
| 多项式 | `0x1021` |
| 初值 | `0xFFFF` |
| RefIn / RefOut | `false / false` |
| XorOut | `0x0000` |
| 计算范围 | 只计算 `NAME,FIELD1,...` 的 ASCII 字节 |

电控接收建议：遇到 `@` 开始缓存，收到 `\n` 后校验；定位最后一个 `*`，对 `@` 与 `*` 之间
的正文计算 CRC。格式错误、CRC 错误或溢出时丢弃整帧。Jetson 对无效帧和未知帧均静默丢弃，
不会返回 NACK，因此电控必须自己做等待超时。

参考 CRC 实现：

```c
uint16_t crc16_ccitt_false(const uint8_t *data, size_t len)
{
    uint16_t crc = 0xFFFF;
    while (len--) {
        crc ^= (uint16_t)(*data++) << 8;
        for (uint8_t i = 0; i < 8; ++i) {
            crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021)
                                 : (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

校验样例：正文 `START,RUN001` 的 CRC 为 `E367`，完整帧是：

```text
@START,RUN001*E367\n
```

## 3. 电控需要发送给 Jetson 的帧

### 3.1 总表

| 电控发送 | 何时发送 | Jetson 正常回复 | 关键要求 |
|---|---|---|---|
| `START,<run_id>` | 一轮比赛开始 | `READY,<run_id>` | 会立即清空旧任务和未完成动作，不能当心跳使用 |
| `REQ,<seq>,PICK[...]` | 车辆/机械臂已到抓取观察位 | `ACCEPTED`，随后 `GRASP_READY` | 只有 `TASK_READY` 状态可发 |
| `REQ,<seq>,CLASSIFY[,<scene>[,<c1>,<c2>,<c3>]]` | 到达观察位后先问"这里是什么颜色" | `ACCEPTED`，随后 `ALIGN_READY` | 候选颜色可省略；建议给本轮 3 色 |
| `REQ,<seq>,PLACE,...` | 已到圆环放置观察位 | `ACCEPTED`，随后 `ALIGN_READY` | 必须给场景和环号 |
| `REQ,<seq>,STACK,...` | 已到暂存区码垛观察位 | `ACCEPTED`，随后 `ALIGN_READY` | 必须给颜色；建议总是给环号 |
| `REQ,<seq>,LOCATE,<scene>[,<ring>]` | 圆环区停下后做车体纠偏 | `ACCEPTED`，随后 `ALIGN_READY` | 必须给场景；环号省略时为 `2` |
| `EXEC,<seq>` | 收到有效 `GRASP_READY` | `EXEC_ACK,<seq>` | 只用于 `PICK`，且必须在 `valid_ms` 内发送 |
| `DONE,<seq>,OK` | 整个机械动作成功 | `DONE_ACK,<seq>,OK` | 必须等 ACK 后才能发下一个 `REQ` |
| `DONE,<seq>,FAIL` | 整个机械动作失败 | `DONE_ACK,<seq>,RETRY` 或 `ERROR,...,GIVE_UP` | RETRY 后 Jetson 自动重识别，不要重发 `REQ` |
| `ABORT,<run_id>` | 中止、急停恢复或重新扫码 | `ABORTED,<run_id>` | 清空任务；重新开始还要再发 `START` |

`run_id` 标识整轮任务，`seq` 标识一次动作请求。二者都是非空 ASCII 字符串，建议不超过 32
字符。每次动作使用唯一且可读的 `seq`，例如 `B1_TP_PICK_1`；收到回复时必须核对同一个 `seq`。

### 3.2 START：开始一轮并等待任务码

```text
电控 → @START,RUN001*E367
Jetson → @READY,RUN001*3274
```

| 序号 | 字段 | 必填 | 含义 |
|---:|---|:---:|---|
| 1 | `run_id` | 是 | 本轮任务标识，Jetson 原样回传 |

`READY` 只表示 Jetson 已进入等待任务码状态，不表示已经扫到二维码。电控随后必须继续等待
`TASK_PLAN`。一个 `START` 只接受第一个合法任务码；要换码必须 `ABORT` 后重新 `START`。

启动顺序必须是：先启动 Jetson 协调器，再由电控发送 `START` 并收到 `READY`，最后让二维码
进入 MaixCAM 画面。二维码若在 `START` 前已被发送，Jetson 会因状态错误拒绝它。

### 3.3 REQ PICK：请求颜色目标

允许三种长度：

| 格式 | 目标颜色来源 | 是否推进 Jetson 自动颜色队列 |
|---|---|---|
| `REQ,<seq>,PICK` | 当前任务队列颜色，场景默认 `TURNTABLE` | `DONE OK` 后推进 |
| `REQ,<seq>,PICK,<scene>` | 当前任务队列颜色 | `DONE OK` 后推进 |
| `REQ,<seq>,PICK,<scene>,<color_id>` | 电控显式指定颜色 | 永不推进 |

推荐电控解析 `TASK_PLAN` 后始终显式发送颜色，恢复最简单；若使用自动队列，只在六次原料区抓取
中使用，并严格等待每次 `DONE_ACK,...,OK` 后再取下一颜色。不要在不了解队列位置时混用两种方式。

```text
@REQ,P001,PICK,TURNTABLE,1*9A78
```

| 序号 | 字段 | 必填 | 允许值/含义 |
|---:|---|:---:|---|
| 1 | `seq` | 是 | 本次请求序号 |
| 2 | `kind` | 是 | 固定为 `PICK` |
| 3 | `scene` | 否 | `TURNTABLE`、`ROUGH` 或 `STORAGE`；省略时为配置值 `TURNTABLE` |
| 4 | `color_id` | 否 | `1` 红、`2` 黄、`3` 蓝、`4` 绿、`5` 黑、`6` 浅蓝；省略则使用队列 |

合法后 Jetson 先回 `ACCEPTED,<seq>,PICK`，识别稳定后再发 `GRASP_READY`。收到
`GRASP_READY` 后电控必须走 `EXEC → EXEC_ACK`，见第 5 节。

### 3.4 REQ PLACE：请求指定数字圆环

```text
@REQ,R001,PLACE,ROUGH,2*C196
```

| 序号 | 字段 | 必填 | 允许值/含义 |
|---:|---|:---:|---|
| 1 | `seq` | 是 | 本次请求序号 |
| 2 | `kind` | 是 | 固定为 `PLACE` |
| 3 | `scene` | 是 | `ROUGH` 或 `STORAGE` |
| 4 | `ring_id` | 是 | 当前实现只允许 `1`、`2`、`3` |

Jetson 会在场景搜索区识别数字，只返回指定环号。稳定后发送 `ALIGN_READY`。`PLACE` 不需要
`EXEC`；电控完成对准和放置后直接发送 `DONE`。

### 3.5 REQ STACK：请求同色码垛目标

```text
@REQ,S001,STACK,STORAGE,5,2*5569
```

| 序号 | 字段 | 必填 | 允许值/含义 |
|---:|---|:---:|---|
| 1 | `seq` | 是 | 本次请求序号 |
| 2 | `kind` | 是 | 固定为 `STACK` |
| 3 | `scene` | 是 | 正式流程固定 `STORAGE` |
| 4 | `color_id` | 是 | `1`～`6`，表示要寻找的第一批同色物料 |
| 5 | `ring_id` | 建议是 | `1`～`3`，用于任务一致性校验；省略时代码默认 `1` |

当前 `STACK` 在 `STORAGE.object_roi` 大区域内找同色物料中心，并不是在固定像素环框内找目标；
`ring_id` 不改变返回坐标，但必须与第一批该颜色在暂存区的环号一致。稳定后发送
`ALIGN_READY`，不需要 `EXEC`，完成码垛后直接发送 `DONE`。

### 3.6 REQ LOCATE：圆环区车体纠偏

车在粗加工区/暂存区（这两个区与地面同高）停下后，用画面里的**锚点圆环**判断车体还差多少。
视觉只回锚点圆环中心相对夹爪末端的偏移，车体偏移由电控换算。

```text
@REQ,L001,LOCATE,ROUGH*BB70
```

| 序号 | 字段 | 必填 | 允许值/含义 |
|---:|---|:---:|---|
| 1 | `seq` | 是 | 本次请求序号 |
| 2 | `kind` | 是 | 固定为 `LOCATE` |
| 3 | `scene` | 是 | `ROUGH` 或 `STORAGE`；**必填**，省略则回 `ERROR,...,MISSING_SCENE` |
| 4 | `ring_id` | 否 | `1`、`2` 或 `3`；省略时为 `2`（车正前方那个工位） |

- 识别方式与 `PLACE` 完全相同（在 `ring_search_roi` 里找同心圆 + 数字模板认环号），所以车停偏了、
  锚点环不在画面中心也能找到；但画面相对“正”的转动超过 `digit_template.rotation_degrees`
  （当前 ±15°）时数字认不出来，会一直等到 `TIMEOUT`。
- 稳定后发 `ALIGN_READY`（`kind=LOCATE`、`target` = 锚点环号），**不需要 `EXEC`**；电控按 `x/y`
  把车开到目标位置后发 `DONE`，收到 `DONE_ACK` 后才能发下一个 `REQ`。
- `x/y` 的含义与 `PLACE` 一致：`unit` 坐标系下锚点圆环中心相对**夹爪末端**的偏移。**`unit=PX`
  时是像素，对车体纠偏没有意义**——必须先把 `ROUGH`/`STORAGE` 标定到 `MM`（两区同高，可共用
  同一个平面矩阵，21 cm 处约 0.2296 mm/px）。
- 建议闭环迭代：每次只走报出偏移的 70~80%，两三次收敛；这比一次性开环修正更抗标定/畸变误差。
- `ALIGN_READY` 第 6 字段 `yaw` 本机不用（只纠位置），固定 `0.000`。
- 和 `PLACE`/`STACK` 一样只允许在 `TASK_READY` 发送；它不属于任务码里的 24 次动作，可以随时插入。

### 3.7 REQ CLASSIFY：报告观察位实际颜色

转盘巡检用：**不告诉 Jetson 要找什么颜色**，而是让 Jetson 告诉电控"当前观察位上是几号色"，
由电控决定抓取 / 移去下一个观察位 / 回底位等转盘。

```text
@REQ,C001,CLASSIFY,TURNTABLE,2,3,4*105B
```

| 序号 | 字段 | 必填 | 允许值/含义 |
|---:|---|:---:|---|
| 1 | `seq` | 是 | 本次请求序号 |
| 2 | `kind` | 是 | 固定为 `CLASSIFY` |
| 3 | `scene` | 否 | 省略时为配置值 `TURNTABLE` |
| 4～6 | `c1,c2,c3` | 否 | 本轮 3 个候选颜色号；给了就**只在这 3 色里选**，能减少误判。个数不限（不一定是 3 个） |

- 回复用 `ALIGN_READY`（字段含义见 4.4）：
  `kind=CLASSIFY`，第 3 字段 `target` 是**实际识别到的颜色号**，`x/y` 是它的中心。
  例：`@ALIGN_READY,C001,CLASSIFY,4,120.000,35.000,0.000,PX,0.930,8*5A0C`
- **不需要 `EXEC`**，和 PLACE/STACK 一样：电控用完这个结果后发 `DONE`，收到 `DONE_ACK` 才能发
  下一个 `REQ`（巡检是多次观察，所以会出现 `CLASSIFY → DONE → 移动 → CLASSIFY → DONE …`）。
- 稳定则发帧；**观察位里什么都没有时不会回帧，会一直等到 `TIMEOUT`**（当前 `timeout_s`）。
  所以电控应把 `CLASSIFY` 的 `TIMEOUT` 当成"这一帧没看到物料"处理（而不是当成错误）。
- 判色与抓取是两条链：`CLASSIFY` 只报颜色；确认要抓之后仍然用 `PICK` + `GRASP_READY` 拿抓取许可。
- 第三个颜色靠**推断**（本轮 3 色互不相同且已看到 2 个，剩下那个必然是目标）——推断放在**电控状态机**里，
  因为只有电控知道机械臂实际去了哪个观察位。参考实现见 `jetson_recognition/turntable_strategy.py`。
- 它不属于任务码里的 24 次动作，可以随时插入。

### 3.8 EXEC：确认采用一次抓取许可

```text
@EXEC,P001*F584
```

| 序号 | 字段 | 必填 | 含义 |
|---:|---|:---:|---|
| 1 | `seq` | 是 | 必须等于当前 `GRASP_READY` 的 `seq` |

只对 `PICK` 使用。电控必须在 `GRASP_READY.valid_ms` 内发送，并等待同序号 `EXEC_ACK` 后才开始
机械动作。若在 ACK 前收到 `GRASP_REVOKED`，本次许可作废，禁止动作。

### 3.9 DONE：报告完整动作结果

```text
@DONE,P001,OK*16FD
```

| 序号 | 字段 | 必填 | 允许值/含义 |
|---:|---|:---:|---|
| 1 | `seq` | 是 | 必须等于当前动作序号 |
| 2 | `result` | 是 | `OK`：完整动作成功；`FAIL`：动作失败 |

“完整动作”不是只完成对准或夹取：

| kind | 何时发送 `DONE OK` |
|---|---|
| `PICK` | 已抓起并放到车载承载位置，整个取料动作结束 |
| `PLACE` | 已按返回坐标对准并放入目标圆环，机械臂退出危险区 |
| `STACK` | 已放到同色第一批物料上完成码垛，机械臂退出危险区 |

收到 `DONE_ACK,<seq>,RETRY` 后保留同一 `seq` 和目标，Jetson 会自动重新识别。当前最多允许
3 次动作结果为 `FAIL`：前两次进入 RETRY，第三次回复 `ERROR,<seq>,GIVE_UP` 并回到可接收新
`REQ` 的状态。

### 3.10 ABORT：中止并清空

```text
电控 → @ABORT,RUN001*4FE0
Jetson → @ABORTED,RUN001*17E3
```

可在任意状态发送。它清空当前请求、任务码和自动颜色队列并回到 `IDLE`。需要继续时必须重新
发送 `START`、等待新的 `TASK_PLAN`，不能直接发送 `REQ`。

## 4. 电控需要从 Jetson 接收的帧

### 4.1 总表

| Jetson 帧 | 字段 | 电控处理 |
|---|---|---|
| `READY` | `run_id` | 确认本轮已建立，继续等待 `TASK_PLAN` |
| `TASK_PLAN` | `task_code,c1,c2,c3,c4,c5,c6` | 保存并解析整轮任务 |
| `ACCEPTED` | `seq,kind` | 请求已受理，保持当前位置并等待识别结果 |
| `TARGET` | 见 4.5 | 可选调试帧；默认关闭，控制逻辑不能依赖 |
| `GRASP_READY` | 见 4.3 | PICK 坐标和短时许可；立即回 `EXEC` |
| `GRASP_REVOKED` | `seq,reason` | 取消尚未 ACK 的抓取，继续等待新的 `GRASP_READY` |
| `EXEC_ACK` | `seq` | 许可锁定，允许开始 PICK 机械动作 |
| `ALIGN_READY` | 见 4.4 | PLACE/STACK/LOCATE/CLASSIFY 稳定坐标；执行后发 `DONE` |
| `DONE_ACK` | `seq,OK/RETRY` | `OK` 才能开始下一请求；`RETRY` 等待本项的新识别结果 |
| `ABORTED` | `run_id/token` | 已回到空闲态 |
| `ERROR` | `seq或NONE,reason[,detail]` | 按第 7 节处理，不要盲目发送下一帧 |

### 4.2 TASK_PLAN：整轮任务

示例：

```text
@TASK_PLAN,156+123+516+231,1,5,6,5,1,6*1CFA
```

| 序号 | 字段 | 含义 |
|---:|---|---|
| 1 | `task_code` | Maix 扫到的原始任务码，格式 `AAA+BBB+CCC+DDD` |
| 2～4 | `c1,c2,c3` | 第一批三个颜色，等于 `AAA` 的三位 |
| 5～7 | `c4,c5,c6` | 第二批三个颜色，等于 `CCC` 的三位 |

原始任务码四组的含义：

| 组 | 示例 | 含义 |
|---|---|---|
| `AAA` | `156` | 第一批颜色及顺序：红、黑、浅蓝 |
| `BBB` | `123` | 第一批三件在粗加工区和暂存区的环号 |
| `CCC` | `516` | 第二批颜色及顺序：黑、红、浅蓝 |
| `DDD` | `231` | 第二批三件在粗加工区的环号 |

`TASK_PLAN` 后六个独立颜色字段是 Jetson 自动 PICK 队列，不包含环号；电控仍需解析第一个
`task_code` 字段取得 `BBB/DDD`。以示例为例：

| 批次 | 顺序 | 颜色 | 粗加工环 | 暂存目标 |
|---:|---:|---|---:|---|
| 1 | 1 | 红 `1` | 1 | 环 1 平放 |
| 1 | 2 | 黑 `5` | 2 | 环 2 平放 |
| 1 | 3 | 浅蓝 `6` | 3 | 环 3 平放 |
| 2 | 1 | 黑 `5` | 2 | 叠到第一批黑色，即暂存环 2 |
| 2 | 2 | 红 `1` | 3 | 叠到第一批红色，即暂存环 1 |
| 2 | 3 | 浅蓝 `6` | 1 | 叠到第一批浅蓝，即暂存环 3 |

同一 `START` 下重复的相同任务码或后续不同任务码都会被 Jetson 忽略，不会再次发送
`TASK_PLAN`。

### 4.3 GRASP_READY：PICK 坐标与短时许可

```text
@GRASP_READY,P001,1,590.000,370.000,PX,590.000,370.000,0.950,8,250*0935
```

| 序号 | 字段 | 类型 | 含义 |
|---:|---|---|---|
| 1 | `seq` | 字符串 | 对应 `REQ` 序号 |
| 2 | `color_id` | 整数文本 | 已识别颜色 `1`～`6` |
| 3 | `x` | 小数 | `unit` 坐标系下的稳定窗口中心 X |
| 4 | `y` | 小数 | `unit` 坐标系下的稳定窗口中心 Y |
| 5 | `unit` | 枚举 | `PX` 或 `MM` |
| 6 | `pixel_x` | 小数 | 原始 1280×720 图像像素 X，左上角为原点、向右增大 |
| 7 | `pixel_y` | 小数 | 原始图像像素 Y，左上角为原点、向下增大 |
| 8 | `confidence` | 小数 | `0.000～1.000` 工程质量分，不是统计概率 |
| 9 | `stable_frames` | 整数文本 | 本次稳定窗口包含的帧数；当前还必须同时满足至少 250 ms |
| 10 | `valid_ms` | 整数文本 | 从 Jetson 生成本帧起，允许发送 `EXEC` 的毫秒数；当前为 `250` |

`unit=MM` 时 `x/y` 是毫米；`unit=PX` 时 `x/y` 与 `pixel_x/pixel_y` 相同，仍不能当毫米用。
`pixel_x/pixel_y` 任何情况下都保留原图坐标。毫米原点与坐标轴由标定矩阵定义，必须与电控坐标系
共同验收。当前状态：`TURNTABLE` 已标定为 `MM`（`k=0.07326 mm/px`，原点为夹爪对准位）；
`ROUGH`/`STORAGE` 仍为 `PX`。

`GRASP_READY` 之后、`EXEC_ACK` 之前 Jetson 持续复检，可能发送：

| 帧 | 原因 | 电控动作 |
|---|---|---|
| `GRASP_REVOKED,<seq>,LOST` | 连续 2 帧没有目标 | 取消本次许可，保持观察位等待新许可 |
| `GRASP_REVOKED,<seq>,UNSTABLE` | 目标仍在但中心失稳 | 取消本次许可，等待新许可 |
| `GRASP_REVOKED,<seq>,EXPIRED` | 250 ms 内未收到 `EXEC` | 取消本次许可，等待新许可 |

迟到的 `EXEC` 会得到 `ERROR,<seq>,BAD_STATE,BUSY`。因此电控只能把 `EXEC_ACK` 当作最终开动
条件，不能只凭收到过 `GRASP_READY` 就动作。

### 4.4 ALIGN_READY：PLACE / STACK / LOCATE / CLASSIFY 结果坐标

PLACE 示例：

```text
@ALIGN_READY,R001,PLACE,2,640.000,370.000,0.000,PX,0.891,8*BD70
```

STACK 示例：

```text
@ALIGN_READY,S001,STACK,5,760.000,370.000,0.000,PX,0.900,8*5719
```

LOCATE 示例：

```text
@ALIGN_READY,L001,LOCATE,2,640.000,370.000,0.000,PX,0.891,8*0824
```

CLASSIFY 示例（第 3 字段是实际颜色号）：

```text
@ALIGN_READY,C001,CLASSIFY,4,120.000,35.000,0.000,PX,0.930,8*5A0C
```

| 序号 | 字段 | 类型 | 含义 |
|---:|---|---|---|
| 1 | `seq` | 字符串 | 对应 `REQ` 序号 |
| 2 | `kind` | 枚举 | `PLACE`、`STACK`、`LOCATE` 或 `CLASSIFY` |
| 3 | `target` | 整数或文本 | PLACE/LOCATE 时为 `ring_id`；STACK 时为 `color_id`；**CLASSIFY 时为实际识别到的 `color_id`** |
| 4 | `x` | 小数 | `unit` 坐标系下的稳定中心 X |
| 5 | `y` | 小数 | `unit` 坐标系下的稳定中心 Y |
| 6 | `yaw` | 小数 | 角度，单位为度；当前 RING/STACK 实现固定返回 `0.000`，预留字段 |
| 7 | `unit` | 枚举 | `PX` 或 `MM` |
| 8 | `confidence` | 小数 | `0.000～1.000` 工程质量分 |
| 9 | `stable_frames` | 整数文本 | 稳定窗口帧数；当前还必须同时满足至少 250 ms |

`ALIGN_READY` 当前不带 `pixel_x/pixel_y` 和 `valid_ms`，也没有 `EXEC` 握手。电控收到并核对
`seq/kind/target/unit` 后执行动作，完成后发送 `DONE`。若 30 s 内没有 `DONE`，Jetson 返回
`ACTION_TIMEOUT` 并结束当前请求。

### 4.5 其他回复帧字段

| 帧 | 完整字段 | 说明 |
|---|---|---|
| `READY` | `run_id` | 原样回传 START 标识 |
| `ACCEPTED` | `seq,kind` | 仅表示请求格式和当前状态允许，不表示已识别到目标 |
| `EXEC_ACK` | `seq` | PICK 许可已接受，之后 Jetson 不再撤销该许可 |
| `DONE_ACK` | `seq,OK` | 本项关闭，可发送下一 `REQ` |
| `DONE_ACK` | `seq,RETRY` | 本项保持，Jetson 自动重新识别 |
| `ABORTED` | `token` | 已清空并回到 `IDLE` |
| `TARGET` | `seq,kind,target,x,y,unit,pixel_x,pixel_y,confidence,stable_frames` | 可选过程观测；当前 `target_report_every=0`，不会发送 |

控制程序不得依赖 `TARGET`。它只用于调试，即使开启也不代表目标稳定，不能触发机械动作。

## 5. 三种请求的严格时序

### 5.1 PICK

| 步骤 | 方向 | 帧/动作 | 电控状态要求 |
|---:|---|---|---|
| 1 | 电控 → Jetson | `REQ,<seq>,PICK,...` | 已到观察位，上一项已收到 `DONE_ACK` |
| 2 | Jetson → 电控 | `ACCEPTED,<seq>,PICK` | 只确认受理，继续等待 |
| 3 | Jetson → 电控 | `GRASP_READY,<seq>,...` | 校验序号、颜色、单位和坐标 |
| 4 | 电控 → Jetson | `EXEC,<seq>` | 必须在 `valid_ms` 内立即发送 |
| 5 | Jetson → 电控 | `EXEC_ACK,<seq>` | 只有收到此帧才允许机械臂动作 |
| 6 | 电控 → Jetson | `DONE,<seq>,OK/FAIL` | 完整动作结束 |
| 7 | Jetson → 电控 | `DONE_ACK,<seq>,OK/RETRY` | OK 后才能开始下一项；RETRY 回到步骤 3 |

若步骤 3 后先收到 `GRASP_REVOKED`，回到等待步骤 3，不发送新 `REQ`。若步骤 5 后动作失败，
仍应发 `DONE,...,FAIL`，不要用新 `REQ` 覆盖。

### 5.2 PLACE / STACK / LOCATE / CLASSIFY

| 步骤 | 方向 | 帧/动作 | 电控状态要求 |
|---:|---|---|---|
| 1 | 电控 → Jetson | `REQ,<seq>,PLACE/STACK/LOCATE/CLASSIFY,...` | 已到观察位，上一项已收到 `DONE_ACK` |
| 2 | Jetson → 电控 | `ACCEPTED,<seq>,PLACE/STACK/LOCATE/CLASSIFY` | 只确认受理，继续等待 |
| 3 | Jetson → 电控 | `ALIGN_READY,<seq>,...` | 校验序号、类型、目标、单位和坐标 |
| 4 | 电控 → Jetson | `DONE,<seq>,OK/FAIL` | 不发 `EXEC`；完整动作结束后发送 |
| 5 | Jetson → 电控 | `DONE_ACK,<seq>,OK/RETRY` | OK 后开始下一项；RETRY 回到步骤 3 |

## 6. Jetson 状态约束

| Jetson 状态 | 正在做什么 | 电控允许发送 |
|---|---|---|
| `IDLE` | 空闲，无任务 | `START`、`ABORT` |
| `WAIT_TASK` | 已 READY，等待 Maix 任务码 | `ABORT`；重复 START 会重新清空并再次 READY |
| `TASK_READY` | 任务已锁定，可接新动作 | `REQ`、`ABORT` |
| `BUSY` | 正在识别 | `ABORT`；不要发新 REQ |
| `WAIT_EXEC` | 已发 PICK 许可，等待 EXEC | 同序号 `EXEC` 或 `ABORT` |
| `WAIT_DONE` | 等机械动作结果 | 同序号 `DONE` 或 `ABORT` |

新 `REQ` 只能在 `TASK_READY` 发送。任何时候再次发送 `START` 都会无条件取消当前动作并清空
任务，因此它不是查询状态或重发确认的命令。

## 7. ERROR 与异常处理

通用格式：

```text
ERROR,<seq或NONE>,<reason>[,<detail>...]
```

| reason | 产生条件 | Jetson 后续状态/电控处理 |
|---|---|---|
| `BAD_START` | START 缺少 `run_id` | 修正格式后重发 START |
| `BAD_STATE,<state>` | 当前状态不允许该命令 | 不要盲目重发；按 state 恢复，必要时 ABORT+START |
| `BAD_TASK_CODE` | Maix 任务码格式非法 | 保持等待任务；重新展示合法二维码 |
| `BAD_REQ` | REQ 字段不足或模式参数不合法 | 当前任务仍可用，修正后用新 seq 发送 |
| `BAD_KIND` | kind 不是 PICK/PLACE/STACK | 修正 kind |
| `MISSING_RING` | PLACE 缺少环号 | 补全 scene 和 ring_id |
| `MISSING_SCENE` | `LOCATE` 缺少场景 | 补上 `ROUGH` 或 `STORAGE` 后重发 |
| `MISSING_COLOR` | STACK 缺少颜色 | 补全 scene 和 color_id |
| `NO_MORE_TARGET` | 自动颜色队列六项已完成 | 不再发自动 PICK；结束本轮或使用显式颜色 |
| `STALE_SEQ` | EXEC/DONE 序号不是当前序号 | 停止动作并核对当前请求，必要时 ABORT 恢复 |
| `EXEC_REQUIRED,WAIT_EXEC` | PICK 未 EXEC 就发送 DONE | 该请求仍在等 EXEC；若许可已过期则等新许可 |
| `BAD_DONE` | DONE 缺少结果 | 用当前 seq 补发合法 DONE |
| `BAD_DONE_RESULT` | 结果不是 OK/FAIL | 用当前 seq 补发 OK 或 FAIL |
| `TIMEOUT` | 识别超过 20 s 无稳定结果 | 当前请求已结束，回到 `TASK_READY`；调整位置后发新 REQ |
| `ACTION_TIMEOUT` | 已许可后 30 s 未收到 DONE | 当前请求已结束，回到 `TASK_READY`；确认机械状态后发新 REQ |
| `GIVE_UP` | 同一动作累计 3 次 FAIL | 当前请求已结束，回到 `TASK_READY`；由电控决定跳过或重开 |

以下情况不会收到 `ERROR`：CRC 错、缺少换行、不是 `@` 开头、未知帧名、同一轮重复/冲突的
Maix 任务码。电控应为每个期望回复设置本地超时；超时后先停止机械动作，优先发送 `ABORT` 建立
明确状态，再重新 `START`，不要用连续的新 `REQ` 猜测 Jetson 状态。

## 8. 一轮比赛的请求对应关系

设任务码为 `AAA+BBB+CCC+DDD`，电控可按下表生成动作。视觉协议总计 24 次 `REQ`：12 次
PICK、9 次 PLACE、3 次 STACK。

| 阶段 | 次数 | REQ | target/ring 来源 |
|---|---:|---|---|
| 第一批原料区抓取 | 3 | `PICK,TURNTABLE,<color>` | `AAA` |
| 第一批粗加工区放置 | 3 | `PLACE,ROUGH,<ring>` | `BBB` |
| 第一批粗加工区取回 | 3 | `PICK,ROUGH,<color>` | `AAA` |
| 第一批暂存区平放 | 3 | `PLACE,STORAGE,<ring>` | `BBB` |
| 第二批原料区抓取 | 3 | `PICK,TURNTABLE,<color>` | `CCC` |
| 第二批粗加工区放置 | 3 | `PLACE,ROUGH,<ring>` | `DDD` |
| 第二批粗加工区取回 | 3 | `PICK,ROUGH,<color>` | `CCC` |
| 第二批暂存区码垛 | 3 | `STACK,STORAGE,<color>,<ring>` | 颜色取 `CCC`；环号取第一批同色物料在 `BBB` 中的位置 |

每个表格行内部仍按三个物料逐项完成，必须收到上一项 `DONE_ACK,...,OK` 后才发送下一项 REQ。
最后一项也只返回普通 `DONE_ACK`，当前协议没有额外的 `TASK_DONE` 帧；整轮是否完成由电控根据
自己的 24 项动作计数判断。结束后可发送 `ABORT,<run_id>` 清空 Jetson 状态。

`LOCATE`（3.6）与 `CLASSIFY`（3.7）不在这 24 次之内：分别是圆环区车体纠偏和转盘巡检，
可以在到达观察位后随时插入，同样要遵守"发下一项之前必须先收到上一项的 `DONE_ACK`"。

## 9. 联调配置与验收

Jetson 当前关键配置：

```json
"coordinator": {
  "maix_transport": "tcp",
  "maix_tcp_host": "0.0.0.0",
  "maix_tcp_port": 5000,
  "mcu_serial": "/dev/serial/by-id/REPLACE_WITH_MCU_UART",
  "baud": 115200,
  "timeout_s": 20.0,
  "action_timeout_s": 30.0,
  "result_valid_ms": 250,
  "require_exec_ack": true,
  "max_attempts": 3,
  "target_report_every": 0
}
```

启动命令：

```bash
python3 -m jetson_recognition.run --config config/jetson.json coordinator \
  --maix-transport tcp --maix-tcp-host 0.0.0.0 --maix-tcp-port 5000 \
  --mcu-serial /dev/serial/by-id/实际电控串口
```

电控侧最小验收清单：

- CRC 样例 `START,RUN001 → E367` 通过，能够处理粘包、拆包和连续多帧；
- START 后先收到 READY，扫码后收到并正确解析 TASK_PLAN 四组信息；
- PICK 严格执行 `GRASP_READY → EXEC → EXEC_ACK → 动作 → DONE → DONE_ACK`；
- 能处理 `LOST/UNSTABLE/EXPIRED` 三种撤销，未收到 EXEC_ACK 时机械臂不动作；
- PLACE/STACK 不发送 EXEC，能区分 ALIGN_READY 第 3 字段是环号还是颜色号；
- `LOCATE` 在 `unit=MM` 时能用来纠偏，`unit=PX` 时清楚它不可用于车体定位；缺少场景能收到
  `MISSING_SCENE`；
- `CLASSIFY` 第 3 字段能区分回的是哪种颜色；候选颜色被限制在给定 3 色内；观察位空时能接受
  `TIMEOUT` 而不是死等；推断在电控侧只用了两个观察结果；
- 所有回复核对 seq，上一项没有 DONE_ACK 时不发送下一项；
- 能处理 FAIL→RETRY、TIMEOUT、ACTION_TIMEOUT、GIVE_UP 和 ABORT 重建状态；
- `unit=PX` 时不把像素直接当毫米；标定后再联合验收 MM 坐标轴和误差。

无硬件可先运行 `python3 tools/simulate_full_control_loop.py`；真实 Maix 和相机、伪电控联调见
[整机闭环测试](整机闭环测试.md)。
