# Jetson 俯视六色识别赛前调参指南

适用对象：第一次在比赛现场调试相机和 HSV 的同学。  
适用流程：固定 ROI → HSV Mask → 轮廓凸包 → 基础几何过滤 → 中心点 → 至少8帧且至少250ms稳定。
六种颜色：红、黄、蓝、绿、黑、浅蓝。

## 1. 第一原则：默认能识别，就不要调

先在最终相机位置、最终背景和最终补光下依次测试六种真实物料：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target red \
  --show-mask --show-fps
```

依次把 `red` 替换为：

```text
red  yellow  blue  green  black  light_blue
```

满足下面四条就直接保留现有参数：

- 目标放在工作区域的中央、四角、亮处和暗处都能识别；
- 目标 Mask 连续完整，背景大部分为黑色；
- 静止目标能快速进入 `STABLE`，移走后能进入 `LOST`；
- 相邻颜色不会互相误识别，尤其是蓝色和浅蓝色。

当前所有颜色统一使用三个保守几何条件：面积范围、宽高比
`0.65～1.55`、距离ROI边缘至少`10 px`。中心由外轮廓凸包计算，减少反光缺口造成的偏移；
稳定结果必须同时满足至少8帧和至少250ms。不要为某一种颜色单独增加形状算法。

不要因为画面“看起来不够漂亮”而调参。识别稳定比肉眼观感重要。

只有出现漏识别、误识别、色温持续漂移、画面过暗/过曝、运动拖影或对焦反复变化时，才继续下面步骤。

## 2. 调参总顺序

严格按这个顺序进行：

```text
固定机械安装和补光
→ 固定曝光、白平衡、对焦位置、增益
→ 确认 ROI
→ 标定六色 HSV
→ 最后调整形态学和面积
→ 全场景复测
```

禁止同时调整相机参数和 HSV。相机画面仍在变化时测出的 HSV 很快会失效。

开始前先备份：

```bash
cp config/jetson.json config/jetson.pre_match.backup.json
```

## 3. 固定比赛现场条件

在锁定相机参数前完成：

1. 固定相机高度、俯视角度和工作距离；
2. 固定补光位置、方向和亮度；
3. 放好真实背景，并在画面内放入六种真实物料；
4. 避免补光直射产生大面积反光；
5. 后续不要再移动相机、镜头和灯。

补光优先保证“均匀”，不是越亮越好。过亮会导致浅色过曝，过暗会迫使曝光或增益升高，引入拖影和噪声。

## 4. 查看当前相机状态（只读）

以下命令在项目根目录执行，针对 Jetson 外接 DECXIN USB 相机；不是 MaixCAM 的扫码相机。
每个新终端先设置设备变量，避免 `/dev/video0` 编号变化后查错设备：

```bash
export CAM="$(python3 -c 'import json; print(json.load(open("config/jetson.json"))["camera"]["device"])')"
readlink -f "$CAM"
v4l2-ctl --list-devices
v4l2-ctl -d "$CAM" --list-ctrls-menus
```

`--list-ctrls-menus` 显示 `min/max/step/default/value`、自动菜单及 `inactive` 等标志。
`default` 是设备默认值，`value` 是控制接口回读值。现场范围以这条命令为准，仓库的
`DECXIN_controls.txt` 只是历史记录。

读取主要参数、取流格式：

```bash
v4l2-ctl -d "$CAM" --get-ctrl=white_balance_automatic,white_balance_temperature,auto_exposure,exposure_time_absolute,gain,focus_automatic_continuous,focus_absolute,saturation,power_line_frequency
v4l2-ctl -d "$CAM" --get-fmt-video --get-parm
```

每秒刷新一次，按 Ctrl+C 停止：

```bash
watch -n 1 "v4l2-ctl -d '$CAM' --get-ctrl=white_balance_automatic,white_balance_temperature,auto_exposure,exposure_time_absolute,gain,focus_automatic_continuous,focus_absolute"
```

这些是设备控制值，不是每一帧绑定的传感器元数据，也不是画面的 HSV。
想看像素颜色，运行 `live --show-hsv --show-mask`，在物料内部移动鼠标观察分位数。

`live` 启动日志里的 `CAMERA_READY.startup_controls` 只是启动时的快照，不会持续更新。
**启动识别会先下发 JSON 中的相机档，因此不能通过重新启动识别来“无干扰读取”原状态。**
查看现有画面对应的控制值，应保持原取流进程运行，在另一个终端用上面的 `v4l2-ctl`。

本机型的自动开关：

| 参数 | 自动状态 | 锁定状态 |
|---|---:|---:|
| `white_balance_automatic` | `1` | `0` |
| `auto_exposure` | `3`（光圈优先，曝光时间自动） | `1`（手动） |
| `focus_automatic_continuous` | `1` | `0` |

## 5. 自动锁参：每次重新自动，稳定后才锁定

**重复运行会重新进入自动档，不会沿用上次的锁定状态。** 原脚本就会先选择
`camera_default_auto`，但只固定等待 10 秒；现在增加了参数、画面稳定性和锁后画面对比。
运行前停止其他取流/调参进程，固定相机和物料，执行：

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --stable-seconds 3 \
  --timeout-seconds 45 \
  --activate
```

纯终端加 `--headless`。脚本默认读写项目 `config/jetson.json`；`--config` 可指定其他文件，
`--camera` 必须是 `/dev/...` 路径。不能用 `--profile camera_default_auto` 覆盖自动档。

新版流程：

1. 回读运行前的控制值，用于失败恢复。
2. 临时使用 `camera_default_auto`，强制自动白平衡 `1`、自动曝光 `3`、自动对焦 `1`，
   去掉该档中冲突的手动色温/曝光/对焦值；不修改 JSON 中的自动档。
3. 开流后再次下发自动档，并在观察期间回读确认自动开关确实为 `1/3/1`。
4. 约每 0.5 秒采样控制值和画面；至少观察 `--settle-seconds`，最近连续
   `--stable-seconds` 同时满足下面的稳定条件才继续。不是到第 10 秒就强行锁定。
5. 应用显式手动覆盖，关闭三个自动算法，写回读数，逐项校验。
6. 丢弃锁定后最初约 1 秒的过渡，再等待一段稳定画面；没有手动覆盖时，还要求与自动阶段画面接近。
7. 全部通过才备份原 JSON、写入并替换配置文件；`--activate` 同时切换默认档。
   新档也记录亮度、对比度、色相、gamma、锐度、背光补偿和变焦，减少未记录状态的影响。

默认稳定判据（现场启发式阈值，不是相机厂商收敛状态）：

| 检查项 | 连续窗口内允许变化 |
|---|---|
| 色温 | 最大值减最小值 ≤ 100 |
| 曝光时间 | ≤ max(2, 窗口中位数的 5%) |
| 对焦位置 / 增益 | ≤ 5 / ≤ 2 |
| 饱和度 / 防频闪 | 不变化 |
| 画面 | 缩至 160×120 后，4×4 分块的每个 BGR 均值变化 ≤ 8 |
| 清晰度 | 缩小灰度图 Laplacian 方差相对变化 ≤ 20%，分母下限 10 |
| 采样连续性 | 至少 4 个样本且覆盖完整窗口；间隔超过 1.5 秒重新累计 |

`--image-tolerance`（默认 8）和 `--sharpness-tolerance`（默认 0.2）可调整画面阈值。
**不要为了让程序通过而直接放宽阈值**，先确认没有人在画面里移动、灯闪烁或相机晃动。
参数一直不变只能说明回读稳定；模糊、过曝或读回旧值也可能稳定，因此必须看真实物料验收。
图像统计也不能证明固件的自动收敛状态，只能拒绝明显漂移和锁后突变。

每个观察阶段最多 `--timeout-seconds`（默认 45 秒），自动阶段至少观察 10 秒；锁后阶段另计时。
取流使用后台线程，控制命令设有 5 秒超时；后端开流和驱动关闭仍可能受到原生驱动阻塞影响。
总运行时间可能超过 45 秒，通常包括自动观察、锁后检查和设备开关时间。

过程日志：`CAMERA_AUTO_OBSERVING`、`CAMERA_LOCK_OBSERVING`；成功才有
`CAMERA_PROFILE_CAPTURED`。超时、自动开关异常、锁后画面突变或白平衡到边界会失败，
不保存新档，并尝试恢复原控制值。`CAMERA_CONTROLS_RESTORED` 表示恢复命令已完成，
若有 `CAMERA_RESTORE_FAILED`，请人工回读检查设备。

显式指定 `--white-balance/--exposure/--focus/--gain` 会主动改变画面，所以这种情况下
跳过“自动阶段与锁定后必须长得一样”的比较，日志为 `skipped_manual_overrides`；
仍要求自动阶段稳定、锁后稳定和控制值校验。它不等于对自动读数真实性的认可。

`--no-save` 禁止写 JSON，但成功后仍会保持设备锁定；不加 `--activate` 也会锁设备，
只是不切换 JSON 默认档。运行中按 q/Esc 或 Ctrl+C 会取消并尝试恢复原控制值。

### 5.1 为什么改变光照后，两次参数仍相同

需要比较具体字段，不能只看整张表：

| 现象 | 如何理解/排查 |
|---|---|
| 三个自动开关都一样 | 锁定结果必然是 `0/1/0` |
| 饱和度总是 `60` | 自动档明确写死，不是自动测出来的 |
| 防频闪相同、增益相同 | 脚本没有优化这些参数；本机型没有在档内启用独立的自动增益开关，不能期待它们随光照变化 |
| 对焦值相同 | 工作距离没变时可能完全正常 |
| 只改灯的亮度，色温相同 | 光源色温可能没变，白平衡不一定需要改变 |
| 光照显著变化，曝光时间也始终相同 | 优先核实自动开关、读回值是否反映自动结果、是否查错设备/文件、是否有其他程序覆盖 |

历史 `DECXIN_controls.txt` 中，自动开启时色温 `4600`、曝光 `156`、对焦 `414` 标记为 `inactive`。
这表示对应手动控制当前不参与控制，**不能单凭 `inactive` 断定读数就是缓存，也不能把这些读数当成可靠的自动收敛证明**。
部分设备固件可能没有通过这些手动控制项反映内部自动结果；驱动也有控制缓存机制，但 Linux 5.15
UVC 对标记为 `AUTO_UPDATE` 的项有缓存失效处理，所以不能未经实测就归因于“Linux 永远读缓存”。
参考 [Linux 5.15 UVC 控制源码](https://github.com/torvalds/linux/blob/v5.15/drivers/media/usb/uvc/uvc_ctrl.c)。

当前仓库的 `competition_locked` 是色温 `4200`、曝光 `80`、对焦 `750`、增益 `0`，这是文件现值，
不是两次实验日志。此前仅靠文件无法确定两次相同的原因；本次补做了宿主机硬件测试：

- USB 确认连接 DECXIN，设备为 `/dev/video0`，MaixCAM 也可见。沙箱没有暴露设备节点，
  不代表宿主机没接摄像头。
- 自动阶段回读开关为 `1/3/1`，但色温/曝光/对焦仍是旧值 `4200/80/750`。
- 自动阶段画面稳定后，把这些值锁回，分块 BGR 均值差约 `30.49`，超过默认阈值 `8`。
- 新脚本因此拒绝保存；测试恢复并回读确认原控制值，正式 JSON 保持不变。
- 第二次从手动锁定状态重新启动，也确认先进入 `1/3/1`；显式覆盖四项手动值后，
  锁后稳定检查和临时 JSON 保存成功。该测试主动跳过自动/手动画面一致性比较，
  不代表自动读数问题已修复；结束仍恢复原控制值，正式配置未改。

这支持“自动模式下回读值未反映真实内部自动结果”的判断，但还不能区分固件和驱动的具体责任，
也不是已完成两种人工切换光照的对照实验。若现场持续出现该报错，应按第 6.5～6.8 节手动调参并保存，
不要无限增加等待时间。

### 5.2 两个终端验证自动模式

终端 A（先停止其他取流进程），保持取流，使用自动档：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target red \
  --camera-profile camera_default_auto --show-hsv --show-fps
```

终端 B 按第 4 节设置 `CAM` 并启动 `watch`。先确认自动开关为 `1/3/1`，
在相同构图下明显增减补光，每次等约 10 秒，记录画面是否先变亮/暗再被拉回，以及回读数值是否变化。
判断曝光响应时改变亮度；判断白平衡响应时需要改变光源色温。

- 画面会自动补偿，曝光读数却一直不变：怀疑设备读回项未反映内部自动结果，应改用手动调参并看图验收。
- 自动开关不是 `1/3/1`：检查 `camera_default_auto` 是否被改，以及是否有其他程序写设备；该项目在开流前下发控制，开流后的状态需实测。
- 自动开关正确，画面也不补偿：检查自动算法是否工作、是否已到能力边界；延长等待只能排除收敛慢，不能解决错误回读。
- 回读会变化，锁参文件却没变：检查日志报错、`saved`、`--no-save`、`--config` 路径，确认看的就是脚本写入的文件。

结束 A 后再运行锁参脚本。不要为了读取参数启动第二个取流程序。
锁参后重新启动 `live --camera-profile competition_locked --show-hsv --show-mask`，
检查颜色、亮度、清晰度是否明显跳变；再重启一次确认能复现。

## 6. 自动结果不好时，怎样手动微调

每次只调整一个参数，修改后重新观察全部六色和背景。

注意：下面的 `capture_camera_profile.py --exposure ...` 等命令仍会重新跑自动阶段，
未显式覆盖的其他参数可能一起改变。真正“只改一项”请用第 6.5 节的 `v4l2-ctl`，
确认后按第 6.7 节保存；不要用重新自动采样代替单项微调。

### 6.1 曝光 `exposure_time_absolute`

- 数值增大：画面更亮，但运动拖影风险增加，可能影响实际帧率；
- 数值减小：画面更暗，但运动轮廓更清楚；
- 有过曝区域时先减曝光；整体太暗时优先增加补光，不要先大幅增加增益。

以已经验证的手动值或可信的自动结果为起点，每次小幅调整。下面的数字只是命令格式示例，应替换为现场测得值：

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --exposure 80 \
  --activate
```

### 6.2 白平衡 `white_balance_temperature`

- 使用白纸或中性灰卡判断，不要只盯着某一个彩色色块；
- 白纸明显偏蓝或偏黄时才调整；
- 每次调整约 `100～300`，观察白/灰是否恢复中性；
- 不同摄像头的视觉变化方向可能不同，以实际画面为准。

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --white-balance 4600 \
  --activate
```

### 6.3 对焦位置 `focus_absolute`

- 把带直线边缘或小文字的物体放在实际工作平面；
- 自动回读可信时记录自动对焦结果；本机已经出现回读旧值的现象，应优先手动看图对焦；
- 每次上下调整约 `5～10`，选择边缘最清楚的值；
- 相机高度固定后保持手动对焦，避免比赛时来回“拉风箱”。

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --focus 414 \
  --activate
```

### 6.4 增益 `gain`

- 光线足够时尽量保持较低值，通常从 `0` 开始；
- 增益升高会放大噪声，使 Mask 出现散点；
- 调整优先级：补光 → 曝光 → 增益。

可以一次覆盖多个已经确认的值：

```bash
python3 tools/capture_camera_profile.py \
  --profile competition_locked \
  --settle-seconds 10 \
  --white-balance 4600 \
  --exposure 80 \
  --focus 414 \
  --gain 0 \
  --activate
```

上述数字只演示写法，不是比赛推荐值。

### 6.5 在另一个终端直接设置当前画面的相机参数

保持一个 `live` 预览进程运行，在另一个终端执行第 4 节的 `export CAM=...`。
先单独关闭三个自动开关，成功后再设置依赖它们的手动值；任意命令报错就先停止后续步骤排查。

```bash
v4l2-ctl -d "$CAM" --set-ctrl=white_balance_automatic=0
v4l2-ctl -d "$CAM" --set-ctrl=auto_exposure=1
v4l2-ctl -d "$CAM" --set-ctrl=focus_automatic_continuous=0
```

下面每行可单独执行，每改一项先观察画面；数字只是示例：

```bash
v4l2-ctl -d "$CAM" --set-ctrl=exposure_time_absolute=80
v4l2-ctl -d "$CAM" --set-ctrl=white_balance_temperature=4200
v4l2-ctl -d "$CAM" --set-ctrl=focus_absolute=750
v4l2-ctl -d "$CAM" --set-ctrl=gain=0
v4l2-ctl -d "$CAM" --set-ctrl=saturation=60
v4l2-ctl -d "$CAM" --set-ctrl=power_line_frequency=1
```

需要调其他成像项也用同一语法，例如 `--set-ctrl=brightness=0`、`--set-ctrl=gamma=100`。
随后用第 4 节的回读命令核对数值，等待几帧看画面实际效果。
这是从后台终端写设备控制，不需要把命令加 `&`，也不需要重启预览。

**这不会修改 JSON。** 当前程序运行中不会反复下发档位，但重新启动程序会按 JSON 覆盖相应字段；
重新插拔的保留行为也不能依赖。调好后务必按下面的方法保存，再重启验收。
如果报 `Device or resource busy` 或写入不被接受，检查自动开关、参数范围和其他调参程序；
具体驱动若不允许带流修改，停止取流后设置并保存，随后再启动验证。

### 6.6 调参到底修改 JSON 的哪些地方

配置文件是 `config/jetson.json`：

| 路径 | 作用 |
|---|---|
| `camera.v4l2_control_profile` | 默认活动档名，当前为 `competition_locked` |
| `camera.v4l2_control_profiles.competition_locked` | 当前锁定档的具体成像参数，应优先改这里 |
| `camera.v4l2_control_profiles.camera_default_auto` | 锁参脚本开始时用的自动档，不是比赛手动档 |
| `camera.v4l2_controls` | 基础控制表；是否下发由所选档的 `_replace_base` 决定 |
| `camera.device` | 相机设备路径 |
| `camera.width/height/fps/fourcc` | 请求分辨率、帧率、像素格式 |
| `camera.backend/backend_fallback` | 取流和解码后端，不是曝光/白平衡 |
| `colors.*.hsv_ranges`、`colors.5.black_threshold` | 图像识别阈值，不控制相机 |
| `camera.calibration_file` 指向的文件 | 内参和畸变校正，不用于调亮度/颜色 |

档位合并规则来自 `UVCCamera._apply_v4l2_controls()`：

- 没选档时，使用 `camera.v4l2_controls`。
- 选中档没有 `_replace_base: true` 时，基础表与档位合并，同名键以档位为准。
- 选中档含 `_replace_base: true` 时，跳过整个基础表，只下发档位里的键。

因此当前只改基础表中的 `exposure_time_absolute` 不会生效；要改
`camera.v4l2_control_profiles.competition_locked.exposure_time_absolute`。
如需固定 `brightness/contrast/hue/gamma/sharpness/backlight_compensation/zoom_absolute`，
也应把已验证的值写入活动档，不能只写在基础表。
`_replace_base` **不代表把设备全部恢复出厂默认值**：没写出的控制项可能沿用设备此前的状态。
自动档同样不是完整的出厂复位。新版锁参会回读并保存上述额外成像项；档内其他自定义键仍不保留。

`live --camera-profile 某档` 只覆盖本次运行的选档，不改 JSON。
正式 `coordinator` 没有这个选项，直接用 JSON 默认档；需要确认 `camera.v4l2_control_profile` 已切换。
修改 JSON 不会热更新，必须重新启动对应程序。

### 6.8 将已调好的当前设备值保存到 JSON（不重新自动采样）

完成第 6.5 节的手动调参，保持预览和参数不变，执行下面命令。
它使用现有脚本的只读回读函数，确认三个开关已手动，再保存；不会创建 `UVCCamera`、
不会启动第二路取流，也不会重新启用自动算法。

```bash
python3 - <<'PY'
import json
from datetime import datetime
from pathlib import Path
from tools.capture_camera_profile import read_controls, VERIFY_CONTROL_NAMES

path = Path('config/jetson.json')
raw = path.read_text(encoding='utf-8')
config = json.loads(raw)
camera = config['camera']
device = camera['device']  # 若预览指定了 --camera，这里也改成相同的 /dev/... 路径
name = 'competition_locked'
# 额外保存本机型的成像控制，避免重启后沿用未记录的旧状态。
extra = ('brightness', 'contrast', 'hue', 'gamma', 'sharpness',
         'backlight_compensation', 'zoom_absolute')
values = read_controls(device, VERIFY_CONTROL_NAMES + extra)
for key, expected in {'white_balance_automatic': 0, 'auto_exposure': 1,
                      'focus_automatic_continuous': 0}.items():
    if values[key] != expected:
        raise SystemExit('请先关闭自动控制再保存: ' + key)
profiles = camera.setdefault('v4l2_control_profiles', {})
profile = dict(profiles.get(name, {}))
profile.update(values)
profile['_replace_base'] = True
profiles[name] = profile
camera['v4l2_control_profile'] = name
backup = path.with_name(path.name + '.' + datetime.now().strftime('%Y%m%d-%H%M%S-%f') + '.bak')
backup.write_text(raw, encoding='utf-8')
path.write_text(json.dumps(config, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
print('backup:', backup)
print(json.dumps({'profile': name, 'device': device, 'controls': profile},
                 ensure_ascii=False, indent=2))
PY
```

换相机后若不支持 `extra` 中某项，先查看控制列表再删掉不支持的项；回读失败时此命令不会写文件。
保存后停止预览，再按第 6.7 节启动并回读检查。已有 `CAMERA_READY` 日志不会因保存而刷新。

### 6.9 参数范围与现场经验

以下范围来自仓库 `DECXIN_controls.txt`；实际以连接的相机报告为准。

| 参数 | 历史范围 | 调整要点 |
|---|---|---|
| `exposure_time_absolute` | 1～10000 | 先满足运动清晰，再兼顾亮度；按约 10%～20% 小步试 |
| `white_balance_temperature` | 2800～6500 | 用工作面中性灰卡/不过曝白纸，每次约 100～300 |
| `focus_absolute` | 0～1023 | 对焦位置，不是毫米焦距；工作面边缘清晰后固定 |
| `gain` | 0～255 | 尽量低，曝光受运动限制后再小步增加 |
| `saturation` | 0～255 | 可先沿用 60，改变它会影响 HSV 的 S |
| `power_line_frequency` | 0/1/2 | 关闭/50 Hz/60 Hz，按现场灯源检查条纹 |
| `brightness/contrast` | -64～64 / 0～95 | 通常先保持稳定，不用它们替代正确曝光 |
| `hue/gamma` | 1～100 / 64～300 | 分别影响色相/明暗关系，标定 HSV 后不要随意改 |
| `sharpness` | 1～65535 | 先对好焦；过锐可能增加轮廓伪影，不能弥补失焦 |
| `backlight_compensation/zoom_absolute` | 0～4 / 0～60 | 固定机位先保持已验证值；变焦还会改变 ROI 和标定关系 |

V4L2 标准曝光单位为 `100 µs`，因此 `80` 对应约 `8 ms`、`156` 对应约 `15.6 ms`。
60 FPS 每帧约 `16.7 ms`，曝光需为读出等过程留余量；不代表设到 166 就一定能跑 60 FPS。
以实际画面拖影和项目输出的 `capture_fps` 为准，而非只看 JSON 中的 `fps: 60`。
曝光单位和对焦语义参考 [Linux V4L2 相机控制文档](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/ext-ctrls-camera.html)。

实操顺序：固定工作距离并对焦 → 用运动物料确定可接受的短曝光 → 调均匀补光 →
必要时小幅增益 → 灰卡白平衡 → 固定饱和度等其余控制 → 重新测六色 HSV。
灯光有条纹时，50 Hz 防频闪设置不保证能解决所有 LED/PWM 问题；检查灯和曝光组合，
优先使用稳定补光。锁参后改变外部光照，画面仍会变亮/暗，这是正常的：锁定的是控制参数，
不是让图像对任何光照都不变。

### 6.10 曝光、对焦、白平衡的具体手调办法

你要改的就是 `camera.v4l2_control_profiles.competition_locked` 中这几项：
`exposure_time_absolute`、`focus_absolute`、`white_balance_temperature`。
`camera.v4l2_controls` 中也有同名字段，但当前档 `_replace_base: true`，改基础表不生效。

**对焦先粗搜，再细搜。** 关闭自动对焦，把小字、棋盘格或真实物料边缘放在实际工作平面。
先保持曝光不变，焦点偏差较大时以约 50～100 的间隔粗搜合法范围，找到清楚的区间；
再以 5～10 的步长细调。每次设置后等约 0.5～1 秒，让镜头停止再判断。
不要把当前 `750` 或旧文档的 `414` 当推荐值；它们只适用于各自的距离。
`focus_absolute` 是镜头对焦位置，`zoom_absolute` 才是变焦控制，二者不能混用。
同时检查中心和四角，以及最低/最高物料表面；末端相机若高度变化明显，一个固定焦点未必覆盖全部位置，
优先固定观察高度，而不是在识别途中反复自动对焦。

**曝光用运动边缘验收。** 若现值 `80`（约 8 ms）有拖影，可以依次试 `60 → 40 → 30`，
一次只改一个值，观察实际运动速度下的轮廓。画面太暗时优先补光，光照允许再微加 gain；
静态画面亮并不代表运动可用。物料反光区大面积纯白，先降低曝光/改变补光角度，
不要靠修改 HSV 找回已经丢失的颜色。不要把 brightness 当曝光替代品。

**白平衡用灰卡判断中性。** 先固定曝光和增益，再把中性灰卡或不过曝的白纸放到真实工作面。
关闭自动白平衡，以当前值为起点上下各试 200，判断哪边能减轻偏蓝/偏黄，再以约 100 细调。
在 `--show-hsv` 预览中也可看灰卡的 BGR50，目标是三个通道较接近，但不要用过曝的白色
（三通道都接近 255）判断白平衡准确。最终以六种真实物料的颜色分离、Mask 和识别稳定为准。
混合色温的灯会让不同区域偏色，一个全局白平衡值不能把所有区域都校正好，应先统一补光。

先用 `v4l2-ctl` 现场调整并回读，满意后用第 6.8 节保存，再重启一键整机入口复核。
相机参数变更后，颜色 HSV 和圆环阈值/模板都应按实际影响复测。

## 7. 固定相机后标定六色 HSV

颜色参数位于：

```text
config/jetson.json → colors
```

每种颜色单独运行：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target light_blue \
  --camera-profile competition_locked \
  --show-mask --show-hsv
```

把鼠标移到物料内部，记录 `HSV05 / HSV50 / HSV95`。同一种物料至少测量：

- 中央、四角；
- 最亮处、最暗处；
- 静止和缓慢移动；
- 两到三个不同位置。

### 7.1 红、黄、绿、蓝、浅蓝

配置格式：

```json
"hsv_ranges": [
  {
    "h_min": 45,
    "h_max": 85,
    "s_min": 80,
    "s_max": 255,
    "v_min": 40,
    "v_max": 255
  }
]
```

简单确定方法：

1. 用多次测量的最低/最高 H 覆盖物料；
2. H 两边只留少量余量，通常先试 `3～5`；
3. `s_min` 略低于测得的最低 S，用于排除灰白背景；
4. `v_min` 略低于测得的最低 V，用于兼容较暗区域；
5. `s_max/v_max` 通常先保持 `255`；
6. 重启程序后观察 Mask，再做小幅修正。

红色跨越 OpenCV H 的首尾，允许保留两段范围：

```text
0～低端上限
高端下限～179
```

蓝色和浅蓝色先继续使用各自独立 HSV 范围，不要提前加入 Lab。

### 7.2 黑色

黑色不判断 H，第一版只调亮度 V：

```json
"black_threshold": {
  "v_max": 80,
  "s_min": 0,
  "s_max": 255
}
```

- 黑色物料漏掉：小幅提高 `v_max`；
- 阴影或深色背景被识别：降低 `v_max`；
- 每次修改约 `5～10`，同时检查有目标和无目标背景。

如果固定补光后仍无法区分黑色和阴影，再考虑未来的局部亮度对比；赛前不要临时堆复杂算法。

## 8. Mask、面积和形态学怎么判断

理想 Mask：目标主体为连续白色，背景基本为黑色，边缘允许有少量缺口。

先调 HSV，只有 HSV 基本正确后才调整：

- 零散小白点：先收紧 HSV；仍存在时把开运算次数从 `1` 调到 `2`；
- 目标内部小黑洞：把闭运算次数从 `1` 调到 `2`；
- 小噪声被画框：提高 `min_area`；
- 真实目标被面积拒绝：降低 `min_area`；
- 不要临时加入长宽比、圆度、多边形或复杂分类器。

每次修改 `config/jetson.json` 后都要退出并重新启动程序，配置不会在线自动刷新。

## 9. 最终验收清单

对每种颜色完成下面测试：

| 测试项 | 合格标准 |
|---|---|
| ROI 中央和四角 | 都能进入 `STABLE` |
| 最亮处和最暗处 | 无持续漏检 |
| 缓慢移动后停止 | 中心跟随，停止后稳定 |
| 移走目标 | 正确进入 `LOST` |


## 10. 现场快速故障判断

```text
六色都正常
→ 不调

所有颜色同时变差，原图也变色/变暗
→ 检查灯和相机锁参，不先改 HSV

只有一种颜色 Mask 全黑
→ 调该颜色 H/S/V

只有黑色异常
→ 调 black_threshold.v_max

Mask 正确但没有框
→ 检查 min_area/max_area

框正确但一直 UNSTABLE
→ 检查多个误轮廓、目标移动和 max_center_delta_px

capture_fps 低而 detect_ms 很小
→ 相机取流/解码问题，和 HSV、ROI 无关
```

## 11. 三条现场纪律

1. 默认能用就不调；
2. 一次只改一个参数，并记录修改前后的值；
3. 先稳定光学输入，再调整识别阈值。
