# 视觉协调层：通信协议与部署（Jetson 识别 + Maix 扫码 + 电控）

本文档描述"导航/抓取由电控负责、视觉只做识别与通信"的完整链路：Jetson 协调层接收 Maix
的任务码，响应电控的识别请求，返回稳定结果与抓取许可。导航、避障、机械臂运动都在电控侧，
本层不涉及。

## 1. 架构与数据流

```text
  MaixCAM Pro           Jetson Nano（coordinator）             电控 (STM32)
 ┌────────────┐   UART A   ┌─────────────────────┐  UART B   ┌──────────┐
 │ 扫码任务码  │ ──@MAIX_QR─>│ 解析任务码→队列      │ ←─REQ/DONE─ │ 导航/抓取  │
 │ UART1      │            │ PickupSession 等待门 │ ──GRASP_READY/ALIGN_READY──>
 │ A19/A18    │            │ RING/STACK 识别      │ ──ERROR/ACCEPTED──> │          │
 └────────────┘            │ OG05B10 相机          │           └──────────┘
                           └─────────────────────┘
```

- **UART A**（`maix_serial`）：Jetson 只读，收 Maix 的 `@MAIX_QR` 帧；
- **UART B**（`mcu_serial`）：Jetson ↔ 电控双向，执行下面的协调协议；
- 两条链路独立，Jetson 收不到 Maix 帧时仍可响应电控（显式指定颜色的 REQ 不依赖任务码）。

帧格式统一为 `@正文*CRC16\n`，与 `new/AUTONOMY_PROTOCOL.md` 一致，电控只需实现一套
CRC16/CCITT-FALSE 编解码。坐标单位：未标定平面返回 `PX`，完成平面标定后返回 `MM`；
电控必须拒绝 `PX` 单位作为毫米动作输入。

## 2. 电控 → Jetson 请求帧

### START（一键启动）

```text
START,RUN001
```

Jetson 进入等待任务码状态，回复 `READY`。

### REQ（请求一次识别）

```text
REQ,0001,PICK                    # 原料区抓取，颜色由任务码队列自动给
REQ,0002,PICK,TURNTABLE,5        # 原料区抓取，显式指定黑色（不消耗队列）
REQ,0003,PLACE,ROUGH,2           # 粗加工区放置：找 2 号圆环中心
REQ,0004,STACK,STORAGE,5,2       # 暂存区码垛：找 2 号圆环内的黑色物料
```

| kind | 参数 | 视觉模式 | 完成时回复 |
|---|---|---|---|
| `PICK` | `[zone[, color_id]]` | 转盘抓取安全门（COLOR + 等待门） | `GRASP_READY` |
| `PLACE` | `zone, ring_id` | RING（找圆环中心） | `ALIGN_READY` |
| `STACK` | `zone, color_id[, ring_id]` | STACK（找指定圆环内同色物料） | `ALIGN_READY` |

`zone` 省略时用配置 `coordinator.scene`（默认 `TURNTABLE`）。Jetson 收到合法 REQ 先回
`ACCEPTED`。

### DONE（完整动作完成 / 失败）

```text
DONE,0001,OK
DONE,0001,FAIL
```

- `OK`：电控**完整动作**已完成——抓取（PICK）是"抓取并放到车载载物平台之后"；放置
  （PLACE/STACK）是"放到目标圆环/码垛之后"。Jetson 收到后才清空当前请求、可接受下一个
  REQ；若刚才是"队列自动取色"，队列已提前推进，无需额外处理；
- `FAIL`：电控动作失败，Jetson 对同一目标重试（最多 `max_attempts` 次），回复
  `DONE_ACK,<seq>,RETRY` 或 `ERROR,<seq>,GIVE_UP`。

### ABORT

```text
ABORT,RUN001
```

清空当前请求，Jetson 回到 `IDLE`。

## 3. Jetson → 电控 回复帧

### 就绪与任务计划

```text
READY,RUN001
TASK_PLAN,156+123+516+231,1,5,6,5,1,6
```

`TASK_PLAN`：任务码解析结果，第二项是两批共 6 件的颜色号顺序（第一批 1、5、6；第二批
5、1、6）。供电控/上位机显示与核对。

### 接受与过程观测

```text
ACCEPTED,0001,PICK
TARGET,0001,PICK,1,550.000,350.000,PX,SEARCHING     # 可选，需 target_report_every>0
```

`TARGET` 用于调试，默认关闭（`target_report_every: 0`）。

### 完成许可

原料区抓取（坐标已稳定、复检通过、可执行抓取）：

```text
GRASP_READY,0001,1,550.000,350.000,PX,550.000,350.000
#          seq 颜色  x        y       unit  像素x     像素y
```

放置/码垛对准完成：

```text
ALIGN_READY,0003,PLACE,2,280.000,370.000,0.000,PX
#          seq  kind  target x     y      yaw  unit
```

### 完成确认与错误

```text
DONE_ACK,0001,OK
DONE_ACK,0001,RETRY
ERROR,0001,TIMEOUT
ERROR,0001,GIVE_UP
ERROR,0001,NO_MORE_TARGET
ERROR,0001,BAD_TASK_CODE
ERROR,0001,BUSY
```

## 4. 协调层状态机

```text
IDLE ──START──> WAIT_TASK ──任务码──> TASK_READY
TASK_READY ──REQ──> BUSY（识别中）
BUSY ──GRASP_READY / ALIGN_READY──> WAIT_DONE
WAIT_DONE ──DONE OK──> TASK_READY
          ──DONE FAIL──> BUSY（重试，≤max_attempts）或 ERROR GIVE_UP
任意 ──ABORT──> IDLE
BUSY ──超时(timeout_s)──> ERROR TIMEOUT → TASK_READY
```

抓取安全门语义（PICK）与 `pickup` 模式一致：只找任务当前颜色 → 目标不在窗口继续等 →
目标运动继续等 → 低速连续保持后累积稳定 → 稳定窗口通过 → 最终复检 → `GRASP_READY`；
`GRASP_READY` 之后丢帧立即撤销（不发出新许可）。

## 5. 配置（`config/jetson.json`）

```json
"coordinator": {
  "maix_serial": "/dev/serial/by-id/REPLACE_WITH_MAIX_UART",
  "mcu_serial": "/dev/serial/by-id/REPLACE_WITH_MCU_UART",
  "baud": 115200,
  "scene": "TURNTABLE",
  "timeout_s": 20.0,
  "max_attempts": 3,
  "target_report_every": 0,
  "pickup": { "capture_zone_px": null, ... }
}
```

`coordinator.pickup.capture_zone_px` 必须先标定（用 `tools/capture_zone_calibrator.py`），
否则 PICK 请求会启动失败。相机沿用 `camera` 段（OG05B10）。

## 6. 运行与联调

### 6.1 Jetson 侧启动

```bash
cd standalone_vision
# 方式一：命令行指定两条串口
python3 -m jetson_recognition.run coordinator \
  --maix-serial /dev/serial/by-id/...MAIX... \
  --mcu-serial /dev/serial/by-id/...MCU...
# 方式二：写入 config 后直接运行
python3 -m jetson_recognition.run coordinator
```

启动后打印 `{"state":"COORDINATOR_READY",...}`。按顺序联调：

1. **电控只发，Jetson 只收**：电控发 `START,RUN001`，Jetson 回 `READY,RUN001`；
2. **Maix 单独扫到任务码**：确认 Jetson 控制台无输出（coordinator 把 `TASK_PLAN` 发给电控
   串口，不在 stdout 打印）；
3. **电控查任务计划**：发 `REQ,0000,PICK` 前先核对电控侧收到的 `TASK_PLAN`；
4. **PICK 闭环**：电控发 `REQ,0001,PICK` → 等 `GRASP_READY` → 执行抓取 → **把物料放到
   车载载物平台** → 发 `DONE,0001,OK`；
5. **超时验证**：转盘故意不放目标，确认 `ERROR,0001,TIMEOUT`。

### 6.2 电脑端模拟电控（无 STM32 时）

Win11 笔记本可用 Python 模拟电控串口，验证协调层逻辑：

```bash
python - <<'EOF'
import serial
s = serial.Serial('COM5', 115200, timeout=1)
s.write(b'@START,RUN001*%04X\n' % crc("START,RUN001"))
# ... 读取 READY、发 REQ、读 GRASP_READY 等
EOF
```

`crc` 即 CRC16/CCITT-FALSE，与 `jetson_recognition/protocol.py` 的 `crc16_ccitt` 一致。

### 6.3 单元测试（无硬件）

```bash
python3 -m unittest discover -s tests -v
```

`tests/test_coordinator.py` 覆盖：任务码解析、队列推进、GRASP_READY 生成、DONE OK/FAIL
重试、显式颜色不消耗队列、超时、PLACE 对准、ABORT、过期 DONE 忽略。

## 7. 排查表

| 现象 | 优先检查 |
|---|---|
| 收不到 Maix 任务码 | `maix_serial` 设备名；Maix 侧 `SERIAL_ENABLED=True`；TX/RX 交叉；共地；3.3V |
| 电控收不到 `READY` | `mcu_serial` 设备名；波特率；电控 CRC 实现是否正确 |
| PICK 启动报错 | `coordinator.pickup.capture_zone_px` 未标定 |
| 一直 `TARGET` 无 `GRASP_READY` | HSV/ROI 未调好；转盘未停；`low_speed_hold_frames`/`stable_frames` 过大 |
| 动作失败反复重试后 `GIVE_UP` | 机械抓取问题，非视觉；检查坐标单位是否 `PX` |
| 坐标是 `PX` | 对应平面未标定（`config/calibration.json`），电控应拒绝执行 |
| 收到 `BUSY` | 上一请求未 `DONE`，电控先补发 DONE 或 ABORT |

## 8. 与 `new/AUTONOMY_PROTOCOL.md` 的关系

帧格式、CRC 和部分帧名（`START`/`ABORT`/`TARGET`/`ERROR`）与自主系统协议一致，便于以后
升级到自主模式时电控侧只需新增导航相关帧。差异点：协调层由电控主动 `REQ` 驱动，不包含
`CMD_VEL`/`ODOM`/`MOVE_REL` 等导航帧。
