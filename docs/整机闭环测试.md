# TCP 任务码与颜色、圆环、码垛完整闭环测试

## 1. 当前完整数据流

```text
MaixCAM识别二维码
  → TCP 10.33.117.105:5000
Jetson协同器解析任务码
  → TASK_PLAN发给电控
电控到达识别位置后发送REQ
  → Jetson启动COLOR、RING或STACK识别
达到模块配置的“至少8帧且至少250ms”稳定条件
  → GRASP_READY或ALIGN_READY
电控执行并发送DONE
  → Jetson允许处理下一项
```

`REQ` 就是当前协议里的“已经到达观察位置，请开始本项识别”。导航仍完全由电控负责，Jetson不会自行判断车辆是否到位。

## 2. 推荐测试顺序

### 第一级：纯软件自动回归

```bash
cd /home/ysu/standalone_vision
python3 tools/simulate_full_control_loop.py
```

它不使用真实相机、Maix和串口，使用六色合成色块和带数字圆环，验证：

- CRC收发；
- TCP字节流分段解析；
- 任务码解析；
- 每轮只锁定第一个合法任务码，后续不同任务码不能覆盖；
- 两批共六件物料的自动颜色队列；
- 第一批：原料抓取、粗加工放置、粗加工取回、暂存区平放；
- 第二批：原料抓取、粗加工放置、粗加工取回、暂存区同色码垛；
- 12次`GRASP_READY/EXEC`、12次`ALIGN_READY`和24次`DONE`；
- 3次`STACK`寻找第一批同色物料中心；
- 任务队列推进到6并最终回到`TASK_READY`。

通过标志：

```json
{"state":"FULL_COMPETITION_SIMULATION_OK","materials":6,"vision_actions":24,"stack_results":3,...}
```

该测试输出较长。只需检查最后是否出现
`FULL_COMPETITION_SIMULATION_OK`，以及`queue_index=6`、`coordinator_state=TASK_READY`。

### 第二级：真实Maix、真实相机、模拟电控

这是当前最推荐的方法，不需要笔记本和串口线。测试脚本创建一个本机伪串口来模拟电控，并自动启动正式协同器：

```bash
cd /home/ysu/standalone_vision
python3 tools/run_hardware_flow_test.py
```

该完整流程测试默认打开两个GUI窗口，不是无头模式：

- `Detection`：显示当前任务状态、固定ROI、候选轮廓、识别中心和稳定状态；
- `Mask`：颜色阶段显示HSV掩码，圆环阶段显示圆环预处理结果。

窗口在完整测试期间持续复用；任务切换只会停止旧识别会话并启动新会话，摄像头不会反复关闭、重开。按 `q`、`Esc` 或终端中的 `Ctrl+C` 停止测试。

运行前停止其他占用相机或5000端口的程序，包括独立的 `maix-net` 和 `live`。

如果Maix尚未插入，脚本仍能先监听`0.0.0.0:5000`。测试脚本会按Sipeed USB硬件标识找到实际的`usb0/usb2` RNDIS接口并激活静态`10.33.117.105/24`；Maix程序仍以`.105`为连接目标。也可单独执行`python3 tools/configure_maix_network.py`检查。

部署`sudo bash tools/install_maix_udev.sh`后，接口会永久命名为`maixcam0`，正常拔插不再依赖`usb0/usb2`的枚举顺序。

按照终端提示操作。脚本现在不是只测第一组，而是按赛题原文执行完整两批六件流程：

1. 脚本模拟电控发送 `START,HW_FLOW`；
2. 在MaixVision运行 `maixcam_pro/main.py`，展示任务二维码，然后按Enter；
3. Jetson通过TCP收到任务码并向模拟电控返回 `TASK_PLAN`；
4. 第一批3件：依次完成原料区抓取、粗加工区放置、粗加工区取回、暂存区平放；
5. 第二批3件：依次完成原料区抓取、粗加工区放置、粗加工区取回；
6. 第二批在暂存区执行3次`STACK`，根据颜色寻找第一批同色物料中心；
7. 每个提示准备好画面后按Enter，脚本才模拟电控发送对应`REQ`。

通过标志：

```json
{"state":"FULL_HARDWARE_FLOW_OK","materials":6,"vision_actions":24,"stack_actions":3}
```

任务码一旦锁定，本轮后续相同码和不同码都会忽略。要重新扫码，请结束当前测试重新启动；正式协议中由电控执行`ABORT`后重新`START`。

### STACK先单独实机验证

完整流程较长，建议先单独确认暂存区同色目标：

```bash
cd /home/ysu/standalone_vision
python3 -m jetson_recognition.run live \
  --mode STACK --scene STORAGE --target 5 --ring 2 \
  --draw-contours --show-mask --show-fps
```

把黑色目标放在`STORAGE`橙色大ROI中的不同位置。当前末端相机方案不会再依赖固定的2号环图像坐标；只要目标颜色正确、轮廓完整且位于大ROI安全边界内，应在至少8帧且至少250ms后显示`STABLE`。`--target`依次改成1～6可以检查其他颜色，`--ring`保留用于校验任务环号。

如所有目标已经预先摆好，可以跳过人工确认：

```bash
python3 tools/run_hardware_flow_test.py --auto
```

### 第三级：真实串口或VOFA人工联调

VOFA适合最后检查真实串口电气连接和手工协议命令，不适合作为第一轮流程测试：人工容易漏发 `EXEC`、用错序号、CRC或者在错误状态发送下一条命令。

不要使用普通USB-A对USB-A线直接连接Jetson和笔记本。两端USB-A通常都是Host端口，这不会自动产生串口。

推荐以下两种接法。

#### 方案A：两个3.3V USB-TTL模块，最容易排查

```text
Jetson USB口—USB-TTL A       USB-TTL B—笔记本USB口
                TX  ─────→  RX
                RX  ←─────  TX
               GND  ──────  GND
```

- 两边都设置115200、8N1；
- 不连接两个模块的VCC；
- Jetson端通常出现 `/dev/ttyUSB0`；
- 笔记本端出现COM端口，VOFA打开该COM端口。

#### 方案B：一个USB-TTL模块连接Jetson 40针UART

USB端接笔记本，TTL端接Jetson Orin Nano开发套件40针排针：

```text
USB-TTL TX → Jetson pin 10 UART1_RXD
USB-TTL RX ← Jetson pin 8  UART1_TXD
USB-TTL GND— Jetson pin 6或pin 9 GND
VCC不接
```

必须使用3.3V TTL电平，不能使用5V TTL或传统RS-232电平。Jetson端设备节点要按实际JetPack检查，不能只凭名称猜测。

## 3. 真实电控的一键启动

入口为项目根目录的 `run_competition.sh`。它启动正式 `coordinator`，默认显示 Detection/Mask，
不创建模拟串口，不替电控发送 START/REQ/EXEC/DONE，也不重新自动锁参。
相机使用 `config/jetson.json` 的活动档；赛前锁参或手调保存应在启动整机前完成。

### 3.1 现在没有下位机，可以先检查命令

```bash
cd /home/ysu/standalone_vision
./run_competition.sh --dry-run
```

这会显示配置文件、相机、活动档、电控串口、波特率及最终命令；不打开设备、不修改网络。
占位串口在 dry-run 中允许存在，**显示命令不代表已通过实机联调**。

### 3.2 电控接上后，找出串口路径

在 Jetson 本机终端执行，比较电控插拔前后的变化：

```bash
ls -l /dev/serial/by-id/
python3 -m serial.tools.list_ports -v
```

优先使用 `/dev/serial/by-id/usb-实际设备名称`，避免 ttyUSB0/ttyACM0 随插拔顺序改变。
若没有 by-id，可检查 `/dev/serial/by-path/`；板载 UART 或没有唯一序列号的转换器以实际节点为准。
不要把 Maix 的 USB 网络接口或其他串口当成电控。

临时指定串口，不修改 JSON：

```bash
./run_competition.sh --mcu-serial /dev/serial/by-id/实际电控串口
```

要以后直接一键启动，先备份并写入真实路径（替换最后一个参数后再执行）：

```bash
cp config/jetson.json config/jetson.before_mcu.backup.json
python3 - /dev/serial/by-id/实际电控串口 <<'PYCONFIG'
import json
from pathlib import Path
import sys
path = Path('config/jetson.json')
config = json.loads(path.read_text(encoding='utf-8'))
config['coordinator']['mcu_serial'] = sys.argv[1]
config['coordinator']['baud'] = 115200
path.write_text(json.dumps(config, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
print(json.dumps(config['coordinator'], ensure_ascii=False, indent=2))
PYCONFIG
```

**正式电控配置是 `coordinator.mcu_serial` 和 `coordinator.baud`，不是顶层 `serial.device`。**
顶层 `serial` 用于独立 live 的可选结果输出，正式协同器不靠 `serial.enabled` 启用通信。
默认 115200、8N1；电控端必须匹配，完整 CRC/字段格式看 [电控对接协议](电控对接协议.md)。

```bash

```

按 q/Esc（GUI）或 Ctrl+C 停止。运行前关闭其他占用相机、电控串口和 TCP 5000 端口的测试程序。

### 3.4 电控与 Maix 的启动顺序

1. Maix 部署并运行 `maixcam_pro/main.py`，暂时不要展示任务二维码。
2. Jetson 执行 `./run_competition.sh`，等待 `COORDINATOR_READY`。
3. 电控发送带正确 CRC 的 `START,<run_id>`，等待 `READY,<run_id>`。
4. 展示二维码，等待 `TASK_PLAN`。
5. 电控到观察位置后再发 `REQ`，按第 4 节握手，不要用重复 START 当心跳。

Maix 保持 `TCP_ENABLED = True`、`TCP_SERVER_HOST = "10.33.117.105"`、`TCP_SERVER_PORT = 5000`。
Jetson 的监听地址 `0.0.0.0` 表示所有本机接口，不能填成 Maix 的连接目标。
一键入口负责启动 Jetson 服务，Maix 程序仍需预先部署运行，电控程序仍需实现正式协议。

当前还没有实物下位机：已完成启动器的无硬件检查和自动化测试，不能将其视为串口电气连接或真实动作验收。

## 4. 重要状态顺序

```text
电控 → START
Jetson → READY
Maix → MAIX_QR
Jetson → TASK_PLAN

电控到位 → REQ PICK
Jetson颜色稳定 → GRASP_READY
电控 → EXEC
Jetson → EXEC_ACK
电控完成动作 → DONE OK

电控到圆环区 → REQ PLACE
Jetson圆环稳定 → ALIGN_READY
电控完成动作 → DONE OK
```

必须先收到上一项的 `DONE_ACK` 再发送下一项 `REQ`。`GRASP_READY` 带有短有效期，电控应立即回复同序号的 `EXEC`。
