# 环境光鲁棒色块识别

规则取消了向下补光后，同一块物料会在不同场馆、不同时间段被不同的环境光照到。
固定 HSV 阈值只对"调参那一刻的光"成立，这是当前
`config/jetson.json` 里颜色参数仍标着 `TEMPORARY SCREEN TEST` 的原因。

本文说明现在的做法、怎么用、以及什么情况下才需要考虑训练模型。

## 1. 结论：先做颜色恒常性，不要先上 YOLO

| 方案 | 成本 | 解决的问题 |
|---|---|---|
| 逐帧白场归一化 + 色块级最近邻分类（本方案） | 无标注、无训练，约 3 ms/帧 | 色温、亮度、阴影渐变导致 HSV 漂移；蓝/浅蓝、黑/阴影重叠误判 |
| YOLO / 分割模型 | 标注数据、训练、TensorRT 部署 | "在哪、是什么形状"；对**色偏本身没有免疫力**，仍要靠颜色恒常性做预处理 |

比赛里颜色是低维问题（6 个色号、已知几何形状），而决赛若出现组合体、遮挡、
杂乱背景，检测能力才真正变重要。所以顺序是：先把颜色做稳，再考虑小模型。

## 2. 现在的识别链路

```text
原始帧
  → 白场归一化（每帧估计光源色温与亮度，重新曝光）
  → HSV inRange 得到各色掩码
  → 轮廓 / 凸包 / 面积 / 边界过滤（与原来一致）
  → 按"整块物料的均值颜色"在每个色号上算距离分
  → 一轮三件用互异指派（3! 全排列取总分最大）定色
  → 多帧投票确认
```

### 2.1 白场归一化（`jetson_recognition/illumination.py`）

场地本身就是标定板：工作面是亚光白色，转盘周围一定看得到一块已知的中性面。
每帧从这个中性面估计光源：

- 取降采样子图，用 `S ≤ 阈值` 找中性（灰白）像素，取其 `V` 作为亮度；
- 各通道分别取 88 分位作为白场电平 → 得到光源的三通道比例；
- 增益 = `canonical_level / 白场电平`，用一张 256 项 LUT 把整帧重新曝光，
  使白场永远落回 `canonical_level`（默认 235）。

这样 HSV 里的 `V` 就变成"反射率"而不是"环境亮度"，色温带来的偏色也被除掉，
一组阈值可以覆盖偏暗、偏暖、偏冷的场馆。

保护机制：

| 情况 | 行为 |
|---|---|
| 找不到中性面（画面里没有白场） | 不处理，原帧直通，`reason=NO_NEUTRAL_REFERENCE` |
| 白场被削顶（`value ≥ 250` 的占比过高） | 不处理，`reason=WHITE_FIELD_CLIPPED`（削顶后无法恢复，只能降曝光） |
| 相邻帧白场突变（手臂伸进画面） | 不跟随，按 `hold_smoothing` 慢速漂移，`reason=HELD_ABRUPT_CHANGE` |
| 增益接近 1（`|gain-1| ≤ gain_epsilon`） | 跳过整帧 LUT，几乎零开销 |

诊断字段在 `detector.last_illumination`：`white_ref_bgr`、`gain`、`reliable`、
`reason`、`overexposed_ratio`、`reference_mode`（STRICT/RELAXED）。

### 2.2 色块级分类（`color_detection.label_classifier`）

`hsv_ranges` 同时充当"原型"：颜色样本先看是否落在某个色号区间内，再按
`hue/saturation/value` 三个方向的加权距离选最近的色号。距离里带一个很小的
"靠近区间中心"项，用来拆开区间重叠的情况（绿与浅蓝在色相上重叠、黑与浅蓝在
亮度上重叠）。**不需要人工标注**，调参位置仍然是那 6 组 `hsv_ranges`。

### 2.3 一轮批次与互异指派（`jetson_recognition/color_batch.py`）

一轮转盘上就是这一轮的三种颜色，所以问题不是"这块是不是我要的颜色"，而是
"这三块分别是什么颜色"。因此：

- `detector.detect_materials(frame, scene, [轮次颜色])` 返回**每一块物料**的中心、
  色号、置信度，以及它对 6 个色号的距离分；
- `assign_distinct()` 在"三块 ↔ 三色"的所有排列里取总分最大的那个，天然不允许
  两块物料被判成同一个色号；
- `assignment_margin()` 给出最优与次优的差距，差距太小说明这一帧不能信。

`detect_color()`（正式 `coordinator` 用的单色路径）行为不变，只是输入帧换成
归一化之后的帧，所以整机链路也同时受益。

## 3. 怎么用

### 3.1 现场测试（推荐入口）

```bash
sudo systemctl stop standalone-vision.service      # 相机独占
python3 tools/test_turntable_color_live.py \
  --task-code 156+123+516+231 --batch 1 --target 1
```

窗口里画的是**归一化之后的画面**（探测器真正看到的东西），底部显示
`LIGHT <reason> ref=[...] gain=[...]`，鼠标探针也读这个画面，所以读数与阈值一致。

JSON 里每帧会输出：

```text
round_batch        本轮判定的三个色号
batch_agreement    最近 N 帧的一致率
batch_stable       连续 N 帧完全一致
materials[]        每块的 blob_id/assigned/center_px/confidence/distance/margin/area
assignment_gap     最优指派与次优指派的差距
illumination       白场诊断
```

A/B 对照：

```bash
--no-illumination   # 关掉白场归一化，回到"原始 HSV"行为
--no-batch          # 回到逐色号独立掩码（旧的 detect_colors 路径）
```

换光照重测：把灯换成暖色/冷色、遮挡部分环境光、把物料放到阴影里，观察
`round_batch` 是否稳定、`materials[].distance` 是否变大。

### 3.2 颜色阈值要不要重调

归一化后白场固定在 235，`V` 的含义变了（≈白场比例），所以：

- 如果原来调参时光照下白场就在 235 附近，阈值基本可以直接用；
- 否则用 `live --show-hsv` 或上面的工具按新读数微调一次 `v_min`；
- 因为有了色块级分类，`hsv_ranges` 只需要保证"物料的主要像素落在自己的区间里"，
  不必再为了排出别的颜色把区间卡得很窄。**建议把各色的 `v_min` 适当放宽**
  （例如原来的 160 改成 120），让掩码更容易连成整块，颜色由距离分决定。

单色查看：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target red --show-hsv --show-mask
```

### 3.3 已知限制

- **白场被削顶**：`overexposed_ratio` 高或 `reason=WHITE_FIELD_CLIPPED` 时，
  归一化会自动关闭。这时应降低 `exposure_time_absolute`，让白场落在 200～240，
  而不是指望算法恢复。
- **全场都是物料**：画面里看不到白场时归一化直通，退化为原行为。
  转盘场景的自然背景足够，粗加工/暂存区的 `object_roi` 也包含地面。
- **黑色与阴影**：阴影在数值上与黑色物料接近；目前靠凸包/圆度/长宽比等形状
  约束区分（与改动前一致）。若现场阴影严重，优先调整机位与补光角度。
- 只做了整帧（低频）归一化，不纠正强局部阴影。局部阴影退化为"亮度下降"，
  由 `v_min` 的余量吸收。

## 4. 什么时候才需要上模型

出现下面任一情况再考虑，且建议只把模型用在"检测/分割"，颜色仍走本链路：

- 决赛物料变成组合体、任意姿态、强遮挡，形状/轮廓约束失效；
- 需要区分颜色接近但材质不同的同类物料；
- 现场背景出现大量与物料同色的干扰物。

即使那时，输入也应该先做白场归一化，否则模型同样会被光照域偏移打崩。
