# 各项视觉识别算法说明

> 历史文档：颜色部分描述的 Lab 原型分类已从默认流程删除。当前颜色算法以根目录
> `JETSON_RECOGNITION_TEST_GUIDE.md` 的 `HSV_CONTOUR_V1` 为准。

## 1. MaixCAM Pro任务二维码

### 1.1 输入与输出

输入是MaixCAM Pro相机画面，输出包括：

- 完整任务码；
- 二维码中心 `(center_x, center_y)`；
- 四条边平均长度；
- 连续确认帧数；
- `STABLE` 状态。

合法格式示例：

```text
156+123+516+231
```

格式校验要求：

- 一共四组，每组三位；
- 第一、三组只能使用颜色号1～6，且组内三种颜色不同；
- 第二、四组是位置号1、2、3的排列；
- 组之间使用 `+`。

### 1.2 实现流程

```text
采集RGB图像
→ QRCodeDetector检测二维码
→ 读取payload
→ 校验任务码格式
→ 计算四角中心和平均边长
→ 相同payload连续4帧
→ 输出QR_STABLE
```

多帧确认用于排除运动模糊和单帧误读。二维码中心和边长目前只用于调试观察，不代表已经实现底盘自动对准。

### 1.3 常见失败原因

- 二维码尺寸太小或失焦；
- 灯光反光导致黑白块饱和；
- 相机与二维码夹角太大；
- 任务字符串包含不符合赛题格式的内容；
- 画面刷新正常但没有连续达到确认帧数。

## 2. 六色物料识别（COLOR）

### 2.1 当前思路

当前采用传统视觉的“目标驱动检测”，不是先把画面中所有物料全部分类。

例如当前任务需要红色物料，调用：

```text
COLOR, 1, TURNTABLE
```

检测器只构造红色掩膜；没有红色时返回 `None`，红色进入ROI时返回其中心。

颜色编号：

| 编号 | 颜色 |
|---:|---|
| 1 | 红色 |
| 2 | 黄色 |
| 3 | 蓝色 |
| 4 | 绿色 |
| 5 | 黑色 |
| 6 | 浅蓝 |

### 2.2 单帧处理流程

```text
裁剪场景ROI
→ 轻度高斯滤波
→ BGR转HSV和Lab
→ 公共S/V条件与Lab原型自动推导的目标色相生成候选（黑色使用L/V暗核心）
→ 开运算去除小噪声
→ 闭运算填补物料内部空洞
→ 提取外轮廓
→ 面积过滤（长宽比、填充率、实心度默认关闭）
→ 腐蚀候选轮廓，只采样不受背景混色影响的内部区域
→ 彩色候选与五个Lab原型比较；距离和分类间隔不合格则拒绝
→ 黑色候选检查内部与外围背景的亮度差
→ 计算轮廓质心
→ 候选质量排序
→ 输出最佳目标
```

默认分类器不再使用五套手工HSV范围硬切彩色目标。红、黄、绿、蓝、浅蓝共用S/V和色相容差，
每种颜色的色相中心由已标定的Lab原型自动推导，先隔离目标以免与有色背景粘成超大轮廓；
颜色原型由 `tools/calibrate_color_prototype.py` 自动采样；第一名相对第二名没有足够距离优势时
主动拒绝。黑色不判断不稳定的H，而是结合L/V暗核心、外围局部亮度差、ROI和几何约束排除阴影。
旧的六套逐色HSV范围已从主配置移除，避免形成两套并存、实际只生效一套的调参陷阱。

### 2.3 置信度

当前 `confidence` 是轮廓稳定性与颜色分类质量的加权结果。赛题目标形状未知，
所以外接矩形长宽比、凸包实心度和填充率不参与硬筛选，也不偏好矩形；几何部分只看
轮廓面积是否足以排除小噪声：

- 面积是否明显大于最小阈值；
- 彩色目标与最近Lab原型的距离及第一/第二名间隔；
- 黑色目标与外围背景的局部亮度差。

它用于过滤噪声和稳定判定，不是神经网络分类概率，也不能直接解释为“95%识别正确”。

### 2.4 多帧稳定

目标需要满足：

- 标签一致；
- 置信度大于 `min_confidence`；
- 连续帧数达到 `stable_frames`；
- 窗口内X/Y极差不超过 `stable_spread_px` 或 `stable_spread_mm`；
- 丢失达到指定帧数后清空历史。

该机制非常适合利用转盘停留期：物料运动时中心持续变化，不容易达到稳定；转盘停下后才输出 `STABLE`。

## 3. 圆环识别（RING）

### 3.1 当前思路

圆环编号来自预配置ROI。例如识别粗加工区2号环时，只在2号环预期区域内检测圆，而不是在整幅图里找圆后再识别数字。

处理流程：

```text
裁剪指定圆环ROI
→ 灰度化
→ CLAHE局部对比度增强
→ 高斯滤波
→ HoughCircles候选圆检测
→ 半径范围过滤
→ 预期半径和远离ROI边缘程度评分
→ 输出最佳圆心
```

霍夫参数包括：

- `min_radius_px`、`max_radius_px`；
- `expected_radius_px`；
- `edge_threshold`；
- `center_threshold`；
- `min_distance_px`。

### 3.2 为什么暂时不做数字OCR

如果1、2、3号环的空间顺序固定，用固定ROI编号更简单、稳定、容易测试。只有实机确认圆环编号会交换、工位可能大幅旋转，才需要数字OCR。

当前程序不能仅凭环内数字自动确定环号，这一点不能在答辩时说成已经实现。

## 4. 工位整体识别（STATION）

工位识别不是简单平均三个圆心，而是：

```text
分别识别多个圆环
→ 得到观测圆心集合
→ 与标定参考点一一对应
→ 最小二乘拟合二维刚体变换
→ 输出平移x、y和偏航yaw
→ 计算拟合残差
→ 残差过大则拒绝结果
```

残差检查可以防止一个圆环误识别为背景圆或物料轮廓后，仍然输出错误工位位姿。

圆形外沿本身关于旋转对称，单独识别一个圆不能得到偏航角；多个具有固定相对位置的圆心才可以估计工位偏航。

## 5. 转盘中心识别（TURNTABLE）

转盘外圆使用与圆环类似的灰度增强和霍夫圆检测，但半径范围更大，并在 `turntable_roi` 中搜索。

输出用途：

- 判断相机观察位置是否对准转盘；
- 给人工调试或以后上位机对准提供圆心偏差；
- 验证抓取窗口与转盘几何关系。

不能提供的量：

- 仅凭圆盘外沿不能判断转盘旋转方向；
- 仅凭某一帧不能判断旋转速度；
- 仅凭圆心不能确定哪个物料即将进入抓取位置。

旋转方向和速度必须通过连续帧跟踪物料中心估计，当前独立项目尚未实现该字段。

## 6. 码垛目标识别（STACK）

第二批物料在暂存区要放到第一批同色物料上，因此最终目标不应继续使用圆环中心。

当前流程：

```text
根据任务位置选择圆环ROI
→ 在该ROI内按颜色检测第一批物料
→ 输出已有物料中心
→ 作为第二批放置对准目标
```

它复用了颜色检测实现，只把搜索范围限制到目标圆环。当前只输出平面中心，没有估计堆叠物料顶面高度；Z高度应由机构尺寸、传感器或电控预设处理。

## 7. 像素坐标与毫米坐标

检测首先得到像素质心。场景完成平面标定后，使用3×3单应矩阵：

```text
[x_mm, y_mm, w]ᵀ = H × [x_px, y_px, 1]ᵀ
```

最后除以 `w` 得到平面毫米坐标。未标定时程序明确返回 `PX`，不会假装成机械坐标。

## 8. 为什么当前先使用传统视觉

当前目标颜色数量有限、物体尺寸明确、工位结构固定，HSV、轮廓和霍夫圆具有以下优势：

- 不需要先采集和标注大量训练数据；
- Jetson Nano实时运行负担小；
- 参数和失败原因可解释；
- 可用合成图与实拍图逐项测试。

如果现场曝光、背景、色差导致传统视觉达不到稳定指标，再根据实拍数据训练轻量目标检测模型。无论内部改成传统视觉还是神经网络，外部 `Measurement` interface 应保持不变。
