# 分板独立测试与串口通信部署手册（Jetson / MaixCAM Pro）

本文档只覆盖**视觉识别 + 识别结果通信**。导航、定位、路径规划、底盘与机械臂控制一律不在
本手册范围内（那部分在 `new/navigation` 与 `new/jetson/autonomy.py`，本文档不涉及）。

目标是让两块板子能**各自独立部署、独立测试**，串口输出在各自配置里可随时开关：

- Jetson Nano + OG05B10：颜色/圆环/工位/转盘/码垛识别，识别结果可选串口输出；
- MaixCAM Pro：任务二维码识别，结果可选串口输出；
- 双板联调：Maix 的二维码帧 → Jetson 接收并转发（可选）。

所有命令默认在 `standalone_vision/` 目录下执行。

---

## 1. 硬件拓扑

```text
              ┌────────────────────────────┐
              │  Jetson Nano               │
              │  ├─ OG05B10 (USB, V4L2)    │  识别：颜色/圆环/工位/转盘/码垛
              │  ├─ UART A (USB转串口)      │  ← 接收 Maix 二维码帧 (bridge)
              │  └─ UART B (USB转串口)      │  → 识别结果/二维码转发到电脑或下位机
              └────────────────────────────┘
                        ▲
                        │ UART (3.3V TTL, TX/RX 交叉, 共地)
              ┌────────────────────────────┐
              │  MaixCAM Pro               │
              │  └─ UART1 (A19 TX, A18 RX) │  扫码：任务二维码
              └────────────────────────────┘
```

- **Jetson 相机**：OG05B10，USB 接口，V4L2，默认 1280×720 @30 MJPG。
- **串口电平**：Maix UART1 是 3.3V 逻辑；Jetson 侧使用 USB 转串口模块时，必须确认该模块
  输出 3.3V TTL（不能直接接不确定电平的 5V UART）。

## 2. 测试矩阵（快速总览）

| 测试内容 | 需要硬件 | 入口 |
|---|---|---|
| 无硬件自动检查 | 无 | `python3 -m unittest discover -s tests -v` |
| Jetson 保存图片识别 | 无 | `python3 -m jetson_recognition.run image ...` |
| Jetson 实时识别 | OG05B10 | `python3 -m jetson_recognition.run live ...` |
| 转盘抓取安全门 | OG05B10 | `python3 -m jetson_recognition.run pickup ...` |
| 抓取窗口标定 | 实拍帧/相机 | `python3 tools/capture_zone_calibrator.py ...` |
| Jetson 识别结果串口 | USB转串口 | `--serial` 或配置 `serial.enabled` |
| Maix 板载扫码 | MaixCAM Pro | MaixVision 运行 `maixcam_pro/main.py` |
| Maix 二维码串口 | UART1 | `SERIAL_ENABLED = True` |
| 双板联调 Maix→Jetson | UART 两根线 | `... run bridge --in-serial ...` |
| 视觉+电控协调层 | OG05B10 + 两条UART | `... run coordinator` |

## 3. Jetson 侧：环境与相机

### 3.1 依赖安装

Jetson Nano（JetPack 4）优先用系统自带的 OpenCV，不要用 PyPI 的 `opencv-python` 覆盖：

```bash
cd standalone_vision
sudo apt update
sudo apt install -y python3-opencv python3-numpy python3-pip v4l-utils
python3 -m pip install --user -r requirements-jetson.txt   # 只有 pyserial
```

确认：

```bash
python3 -c "import cv2, numpy, serial; print(cv2.__version__, numpy.__version__)"
```

普通 PC（Win11 笔记本调试）可以：

```bash
python3 -m pip install --user -r requirements-pc.txt       # numpy opencv-python pyserial
```

### 3.2 相机设备名

OG05B10 插上后查找稳定设备名（不要长期依赖 `/dev/video0`）：

```bash
v4l2-ctl --list-devices
ls -l /dev/v4l/by-id/
```

把结果填入 `config/jetson.json` 的 `camera.device`，例如：

```json
"camera": {
  "device": "/dev/v4l/by-id/usb-...-video-index0",
  "width": 1280,
  "height": 720,
  "fps": 30,
  "fourcc": "MJPG",
  "calibration_file": "config/calibration.json"
}
```

> 相机支架/高度/姿态一旦变化，ROI、HSV、标定都要重新确认，不能只改设备名。

### 3.3 串口配置段（新增，识别结果输出开关）

`config/jetson.json` 新增：

```json
"serial": {
  "enabled": false,
  "device": "/dev/serial/by-id/REPLACE_WITH_RESULT_UART",
  "baud": 115200
}
```

- `enabled: false`（默认）：不开串口，识别结果只打印到控制台 JSON；
- `enabled: true`：识别结果自动发到 `device`；
- 命令行 `--serial <设备>` 优先级更高：显式传入时使用命令行设备，忽略配置。

串口设备名同样用 `ls -l /dev/serial/by-id/` 查找。

## 4. Jetson 侧：识别测试

### 4.1 无硬件自动检查

```bash
cd standalone_vision
python3 -m unittest discover -s tests -v
python3 -m compileall -q jetson_recognition tools tests
```

验证识别会话稳定性、合成红色物料检测、串口 CRC 编解码。Maix 代码依赖板端 `maix` 模块，
不能在普通 CPython 中执行。

### 4.2 保存图片单帧识别（无相机）

```bash
# 颜色（1=红 ... 6=浅蓝）
python3 -m jetson_recognition.run image samples/red.jpg \
  --mode COLOR --scene ROUGH --target 1 --show

# 圆环 / 工位 / 转盘 / 码垛
python3 -m jetson_recognition.run image samples/ring.jpg --mode RING --scene ROUGH --target 1 --show
python3 -m jetson_recognition.run image samples/station.jpg --mode STATION --scene ROUGH --show
python3 -m jetson_recognition.run image samples/turntable.jpg --mode TURNTABLE --scene TURNTABLE --show
python3 -m jetson_recognition.run image samples/stack.jpg --mode STACK --scene STORAGE --target 1 --ring 2 --show
```

无桌面环境用 `--save result.jpg`，不要 `--show`。检测到目标退出码 0，未检测到退出码 2，
适合脚本批量统计召回率。

### 4.3 实时识别（接 OG05B10）

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target 1 --camera /dev/video0
```

SSH 无图形桌面时加 `--headless`，结果以一行一个 JSON 输出：

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target 1 --headless
```

窗口按 `q`/`Esc` 退出。出现 `STABLE` 表示连续帧位置和置信度满足配置阈值。

### 4.4 转盘抓取安全门（pickup 模式）

目标流程：只检测任务当前颜色 → 窗口内没有就等转盘 → 目标进入但仍在运动就等 →
停留且连续低速保持后累积稳定 → 最终复检 → 输出 `GRASP_READY`。

`pickup` 模式要求先标定 `capture_zone_px`，否则会拒绝启动。用可视化标定工具：

```bash
# 在实拍帧上拖拽（黄=外框，绿=内缩安全区），按 s 保存
python3 tools/capture_zone_calibrator.py --image frame.jpg --target 1 --scene TURNTABLE
# 或接相机实时标定
python3 tools/capture_zone_calibrator.py --camera 0 --target 1 --scene TURNTABLE
# 无桌面环境用命令行矩形
python3 tools/capture_zone_calibrator.py --image frame.jpg \
  --x 340 --y 70 --w 600 --h 600 --headless --save
```

保存后测试完整安全门：

```bash
python3 -m jetson_recognition.run pickup --target 1 --scene TURNTABLE --camera /dev/video0
```

状态顺序：

```text
SEARCHING    窗口内无目标，继续等转盘
TRACKING     目标在窗口外
MOVING       目标在窗口内但速度超限，继续等
SETTLING     速度低于阈值连续 low_speed_hold_frames 帧（目标减速）
FINAL_CHECK  稳定窗口通过，复检中
GRASP_READY  复检通过，允许进入抓取流程（ready_rising_edge=1 仅首次达成）
```

安全语义：`GRASP_READY` 之后只要丢一帧就立即撤销许可（`TARGET_LOST_AFTER_READY`）。
超时输出 `TARGET_TIMEOUT`（默认 20s，`--timeout` 可改）。

## 5. Jetson 侧：识别结果串口输出

两种开启方式，任选其一：

### 5.1 命令行（临时）

```bash
# 实时识别 + 串口输出
python3 -m jetson_recognition.run \
  --serial /dev/ttyUSB0 --baud 115200 \
  live --mode COLOR --scene TURNTABLE --target 1 --headless

# 转盘抓取安全门 + 串口输出
python3 -m jetson_recognition.run \
  --serial /dev/ttyUSB0 \
  pickup --target 1 --scene TURNTABLE
```

> `--serial` 是全局选项，必须写在子命令（`live`/`image`/`pickup`）之前。
> 不传 `--serial` 时不会导入 PySerial，也不会访问任何串口设备。

### 5.2 配置开关（正式运行/长期）

把 `config/jetson.json` 的 `serial` 段改为：

```json
"serial": { "enabled": true, "device": "/dev/ttyUSB0", "baud": 115200 }
```

之后直接运行（不再加 `--serial`）：

```bash
python3 -m jetson_recognition.run live --mode COLOR --scene TURNTABLE --target 1 --headless
python3 -m jetson_recognition.run pickup --target 1 --scene TURNTABLE
```

识别结果帧示例（`SERIAL_OUTPUT.md` 有完整说明）：

```text
@VISION_RESULT,STABLE,COLOR,1,550.000,350.000,0.000,0.950,PX,5*XXXX
@GRASP_READY,GRASP_READY,1,550.000,350.000,PX,550.000,350.000,0.950,0.000,5,3,200,1*XXXX
```

## 6. MaixCAM Pro 侧：部署与板载测试

### 6.1 项目结构

用 MaixVision 新建项目，把这两个文件放在项目根目录（保持相对路径）：

```text
maixcam_pro/
├─ config.py
└─ main.py
```

### 6.2 参数配置（`maixcam_pro/config.py`）

```python
CAMERA_WIDTH = 640
CAMERA_HEIGHT = 480
CAMERA_FPS = 30

DISPLAY_ENABLED = True       # 板载屏幕显示
CONFIRM_FRAMES = 4           # 连续确认帧数
RESET_AFTER_MISSED_FRAMES = 8

SERIAL_ENABLED = False       # 二维码串口输出开关
UART_DEVICE = "/dev/ttyS1"
UART_BAUD = 115200
UART_TX_PIN = "A19"
UART_RX_PIN = "A18"
```

- `SERIAL_ENABLED = False`（默认）：只跑识别，不打开 UART1，断开的 Jetson 不影响扫码测试；
- `SERIAL_ENABLED = True`：稳定确认后通过 UART1 发送 `@MAIX_QR,...` 帧。

### 6.3 板载独立测试

MaixVision 中直接运行 `main.py`。控制台出现 `MAIX_STANDALONE_QR_READY serial=False`
表示启动成功。屏幕会显示：

- 未发现二维码：`SEARCHING QR` / 二维码格式错误：`INVALID QR`（红字）；
- 发现合法任务码：画绿/黄框 + `任务码 确认帧数/4`；
- 连续 `CONFIRM_FRAMES` 帧一致后：`QR_STABLE payload=123+123+456+231 ...`。

任务码必须是**四组三位码**格式（如 `123+123+456+231`），否则判为无效。验证流程：

1. 依次显示合法码、非法码、无码画面；
2. 二维码快速移动、倾斜、强反光/阴影；
3. 二维码离开画面后确认状态是否在 `RESET_AFTER_MISSED_FRAMES` 帧内清空。

## 7. Maix 侧：二维码串口输出

把 `SERIAL_ENABLED` 改为 `True` 并重新运行。用 USB 转串口把 Maix UART1 接到电脑：

```text
Maix A19 (TX) ──> 电脑 RX
Maix A18 (RX) ──< 电脑 TX
地线连接，波特率 115200, 8N1, 3.3V TTL
```

电脑端（Win11 可用 PowerShell / Python）查看：

```bash
python -c "import serial; s=serial.Serial('COM3',115200,timeout=1);\nwhile True:\n line=s.readline(); print(line.decode('ascii','replace'), end='')"
```

稳定后输出：

```text
@MAIX_QR,123+123+456+231,320.0,240.0,120.0,4,STABLE*XXXX
```

字段：任务码、中心 x、中心 y、平均边长、确认帧数、状态。

## 8. 双板联调：Maix → Jetson 转发（bridge）

Jetson 用 `bridge` 子命令接收 Maix 的二维码帧，校验 CRC 后打印 JSON，并可转发到第二个串口。

### 8.1 接线

```text
Maix UART1 A19(TX) ──> Jetson USB转串口 RX
Maix UART1 A18(RX) ──< Jetson USB转串口 TX
共地, 115200, 3.3V
```

Jetson 上先确认端口：

```bash
ls -l /dev/serial/by-id/
```

### 8.2 只接收并打印

```bash
python3 -m jetson_recognition.run bridge --in-serial /dev/ttyUSB0 --baud 115200
```

正常后每收到一帧打印一行 JSON：

```json
{"frame": "MAIX_QR", "fields": ["123+123+456+231", "320.0", "240.0", "120.0", "4", "STABLE"]}
```

CRC 错误或非协议行会被丢弃。

### 8.3 接收并转发到第二串口（给电脑/下位机）

```bash
python3 -m jetson_recognition.run bridge \
  --in-serial /dev/ttyUSB0 --out-serial /dev/ttyUSB1 --baud 115200
```

`--in-serial` 接 Maix，`--out-serial` 接电脑/下位机，转发的是原始帧。

### 8.4 验证顺序

1. Maix 单独跑通（第 6、7 节）；
2. Jetson 单独跑通识别（第 4、5 节）；
3. 接上 Maix→Jetson 的线，Jetson 跑 `bridge`，扫一个合法二维码，确认 JSON 输出；
4. 再接 `--out-serial`，电脑上确认收到原始 `@MAIX_QR,...` 帧。

> 若要让**视觉+电控整机闭环**（Jetson 解析任务码、响应电控 REQ、回 GRASP_READY，而
> 导航/抓取全由电控负责），请改用 `coordinator` 模式，完整双向协议与联调步骤见
> `docs/06_协调层通信协议与部署.md`。

## 9. 串口协议速查

帧格式：

```text
@NAME,FIELD,...*CRC16\n
```

- 正文为 ASCII，CRC 为 CRC16/CCITT-FALSE，计算范围是 `@` 之后、`*` 之前的正文；
- 单帧正文最多 176 字节；字段不得含逗号、`*`、`@`、换行；
- CRC 错误/非法帧直接丢弃。

| 发送方 | 帧名 | 说明 |
|---|---|---|
| Jetson | `VISION_RESULT` | 单帧/实时识别结果（live/image） |
| Jetson | `PICKUP_STATE` | 转盘抓取过程状态 |
| Jetson | `GRASP_READY` | 转盘抓取许可（末尾含 `ready_rising_edge`） |
| Maix | `MAIX_QR` | 稳定确认的任务二维码 |

解码/编码都在 `jetson_recognition/protocol.py`：`encode_frame` 发送、`decode_frame` 解析
（`decode_frame` 供 bridge 使用，返回 `(name, fields)` 或 `None`）。

## 10. 故障排查表

| 现象 | 优先检查 |
|---|---|
| 相机打不开 | 设备名、权限、是否被其它进程占用、V4L2 格式 |
| 所有颜色都检测不到 | ROI、曝光、BGR/HSV、最小面积 |
| 黑色大量误报 | 阴影、亮度阈值、曝光锁定 |
| 蓝色/浅蓝混淆 | 饱和度/亮度范围、白平衡、实物色差 |
| 有单帧结果但不 `STABLE` | 坐标抖动、转盘仍运动、置信度、稳定帧数 |
| `pickup` 启动报错 | `capture_zone_px` 未标定，先跑标定工具 |
| Jetson 串口没输出 | `--serial` 未传且 `serial.enabled=false`；设备名；波特率；TX/RX 交叉；共地 |
| Maix 串口没输出 | `SERIAL_ENABLED` 未改；引脚复用；电平 3.3V；TX/RX 交叉；共地 |
| bridge 收不到帧 | `--in-serial` 设备名；波特率；Maix 侧是否 `SERIAL_ENABLED=True`；接线 |
| 输出 `PX` 而非 `MM` | 该场景平面尚未标定（`config/calibration.json`） |

## 11. 验收指标

- 六种颜色分别测试，负样本不允许输出错误 `STABLE`；
- 静止目标坐标抖动明显小于夹爪容差；
- 运动物料不应在抓取窗口外输出抓取许可；
- 转盘停留后应在停留时间内完成稳定确认（`low_speed_hold_frames + stable_frames +
  final_recheck_frames` 对应的帧数）；
- Maix 合法码稳定输出 `QR_STABLE`，非法码/无码不输出；
- 串口帧 CRC 正确，电脑端可逐行解析；
- bridge 转发后电脑端收到的 `@MAIX_QR` 与 Maix 发送内容一致。
