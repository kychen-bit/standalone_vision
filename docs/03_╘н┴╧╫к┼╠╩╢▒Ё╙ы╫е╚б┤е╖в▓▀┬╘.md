# 原料转盘识别与抓取触发策略

## 1. 直接回答：看到第一个位置后怎么处理

推荐第一版采用：

> 按任务顺序只寻找当前需要的颜色；如果抓取窗口里的物料不是所需颜色，不抓取、不必记住它的槽位，继续等待转盘把目标颜色送到抓取窗口；目标进入窗口并在转盘停留期连续稳定后，才输出“视觉准备完成”。

例如任务第一件是红色：

```text
当前窗口是蓝色 → 红色检测返回None → 等待
当前窗口是黄色 → 红色检测返回None → 等待
红色进入窗口但仍在运动 → 有检测但未STABLE → 等待
红色停在窗口且连续5帧稳定 → 输出STABLE → 允许进入抓取流程
```

这不是“识别错误就等”，而是目标驱动搜索：视觉从一开始就知道当前只需要红色。

## 2. 为什么推荐等待式策略

赛题给出的转盘特性是：

- 转向随机；
- 6～10秒一圈；
- 三个物料约120°分布；
- 每圈会周期停留，但次数和停留时间以现场为准；
- 停止位置存在误差。

因此不适合在第一版中预先假定“1号槽顺时针下一格一定是2号槽”。等待式策略不依赖转向、初始相位和停止误差。最多等待目标转过一圈，通常是可接受的；真正的时间瓶颈更可能是机械臂动作而不是颜色判断。

## 3. 抓取窗口而不是整盘识别

自动抓取时不能使用“整盘任何位置检测到目标就抓”的逻辑。应该定义两个区域：

```text
search_roi：看见目标并持续跟踪的较大区域
capture_zone：只有目标中心进入这里，才有资格判定可抓
```

抓取窗口通常围绕夹爪投影中心设置，并比完整物料略大。`capture_zone` 应比 `search_roi` 小，留出边缘安全余量，防止只看到半个物料时误触发。

当前配置的 `TURNTABLE.object_roi` 仍覆盖较大圆盘区域，适合识别算法测试，不适合直接产生抓取许可。单板测试阶段可以先把它临时缩小到实际抓取窗口；正式自动抓取前，还应在代码中增加独立 `capture_zone` 和中心内缩判定。

## 4. 推荐状态机

```text
ENTER_RAW_AREA
      ↓
OBSERVATION_POSE       夹爪相机到固定观察高度和姿态
      ↓
CHECK_TURNTABLE        可选：检查转盘圆心是否在允许范围
      ↓
WAIT_TARGET            只检测任务队列当前颜色
      │
      ├─ 未检测到目标 ─────────────┐
      │                            │
      ├─ 检测到但在capture_zone外 ─┤ 继续等待/跟踪
      │                            │
      ├─ 在窗口内但位置仍变化 ──────┘
      ↓
TARGET_STABLE          连续N帧、置信度和位置抖动合格
      ↓
FINAL_RECHECK          抓取前最后确认目标仍在窗口
      ↓
REQUEST_PICK           把目标位置交给抓取流程
      ↓
WAIT_PICK_RESULT
      ├─ 成功 → 从任务队列取下一个颜色 → WAIT_TARGET
      └─ 失败 → 抬升/复位 → WAIT_TARGET或ERROR
```

`PickupSession`（`jetson_recognition/pickup.py`）目前实现了从 `WAIT_TARGET` 到 `GRASP_READY` 的整条视觉安全门：只检测任务当前颜色、目标中心必须在 `capture_zone` 内缩出的 `safe_zone` 内、转盘运动期间不进稳定窗口、连续低速保持后才开始累积、稳定后再做最终复检。它没有实现机械臂状态和 `REQUEST_PICK`，抓取动作仍由上位机/电控在收到 `GRASP_READY` 后执行。

## 5. 推荐判定条件

视觉允许抓取至少需要同时满足：

1. 颜色等于任务队列当前颜色；
2. 目标中心在 `capture_zone` 内，而不是只在画面中；
3. 轮廓完整，面积和几何质量合格；
4. 连续帧数达到5～10帧；
5. 连续窗口内位置极差小于阈值；
6. 最近一帧时间戳未过期；
7. 抓取开始前再次检测仍有效。

建议把“检测稳定”和“允许抓取”分成两个状态：

```text
STABLE：视觉测量稳定
GRASP_READY：稳定 + 在安全抓取窗口 + 结果新鲜
```

`PickupSession` 已经输出 `GRASP_READY`（视觉侧允许抓取），并附带 `ready_rising_edge` 上升沿标记，方便上位机在首次达成时只动作一次；串口帧里也追加了该字段。它不执行夹爪动作，机械臂下降与夹爪闭合由上位机/电控在收到许可后完成。

## 6. 是识别当前物料，还是只检测目标颜色

### 方案A：只检测当前目标颜色（推荐第一版）

优点：

- 逻辑最简单；
- 不会因为蓝色和浅蓝分类竞争而选错当前物料；
- 与严格的任务抓取顺序天然一致；
- 当前 `COLOR` 模式已经支持。

缺点：

- 看见非目标物料时只知道“目标不存在”，不知道它具体是什么颜色；
- 不能提前预测还有多久目标会到来。

### 方案B：每帧把当前物料分类为六种颜色

优点：

- 调试界面信息更直观；
- 可以记录转盘颜色序列；
- 连续跟踪后可以预测目标到达时间。

缺点：

- 需要解决多个颜色掩膜重叠和分类竞争；
- 转向随机、抓取后物料缺位，使槽位状态维护更复杂；
- 对完成第一版抓取不是必需能力。

因此建议比赛主链先采用方案A，另做一个 `CLASSIFY_COLOR` 调试模式，不让调试功能进入抓取许可主链。

## 7. 转盘是否需要先识别圆心

如果夹爪相机每次都能由机构到达重复的观察姿态，可以直接观察固定抓取窗口，不必每件物料都先识别转盘圆心。

在这些情况下建议先做 `TURNTABLE`：

- 机器人停车或机械臂观察姿态重复性较差；
- 抓取窗口相对转盘中心的偏差会明显影响抓取；
- 需要先用转盘圆心做一次小范围XY修正。

转盘圆心稳定只说明观察几何对准，不说明目标物料已经到达。

## 8. 静态抓取、分步重测和动态抓取

### 固定高度等待停留后抓取（推荐起步）

```text
固定观察高度等待目标
→ 目标停留并稳定
→ XY对准
→ 停止视觉修正
→ 垂直下降
→ 闭合夹爪
```

利用赛题转盘周期停留，风险最低。

### 分步下降重测（第二阶段）

```text
XY对准
→ 下降一段
→ 停止重测
→ 再对准
→ 再下降
```

适合夹爪机械误差较大但还不具备连续速度控制的系统。

### 连续动态抓取（后续）

机械臂下降期间持续检测并修正XY，适合停留时间不够或不停转抓取。它需要连续视觉伺服、目标丢失立即停机和速度有效期保护，当前项目没有实现。

## 9. 超时和异常

建议从进入 `WAIT_TARGET` 开始设置15～20秒超时，覆盖至少一圈加余量。

超时后不能默认“当前位置就是目标”，应：

1. 停止抓取动作；
2. 检查相机帧是否正常；
3. 检查目标颜色是否来自合法任务码；
4. 检查ROI、曝光和HSV阈值；
5. 允许重新观察一次；
6. 仍失败则记录 `TARGET_TIMEOUT`。

目标丢失也不能把误差设置成零，因为零误差会被误认为已经对准。

## 10. 当前阶段怎么实际测试

第一阶段不要接夹爪动作，只观察。有两种入口：

### 10.1 只看颜色识别（原有 live 模式）

```bash
python3 -m jetson_recognition.run live \
  --mode COLOR --scene TURNTABLE --target 1 --camera /dev/video0
```

依次测试1～6号颜色。转盘旋转时观察：

- 非目标颜色经过是否始终不输出目标；
- 目标颜色进入ROI后能否检测；
- 目标运动时是否不会过早 `STABLE`；
- 转盘停留后多久输出 `STABLE`；
- 目标离开后稳定窗口是否清空；
- 黑色阴影是否引起误报；
- 蓝色和浅蓝是否混淆。

### 10.2 先标定抓取窗口，再测完整安全门

`capture_zone_px` 未配置时 `pickup` 模式会拒绝启动。先用可视化标定工具在实拍帧上拖拽画出夹爪投影对应的窗口：

```bash
python3 tools/capture_zone_calibrator.py --image frame.jpg --target 1 --scene TURNTABLE
python3 tools/capture_zone_calibrator.py --camera 0 --target 1 --scene TURNTABLE
```

左键拖拽画外框（黄色），内缩安全区自动显示（绿色）；按 `s` 写回 `config/jetson.json` 的 `pickup.capture_zone_px`。无桌面环境用命令行矩形加 `--headless --save`：

```bash
python3 tools/capture_zone_calibrator.py --image frame.jpg --x 340 --y 70 --w 600 --h 600 --headless --save
```

标定后测试完整安全门：

```bash
python3 -m jetson_recognition.run pickup --target 1 --scene TURNTABLE --camera /dev/video0
```

状态顺序：窗口内无目标 → `SEARCHING`；目标进入但速度超限 → `MOVING`；速度低于阈值并连续 `low_speed_hold_frames` 帧 → `SETTLING`（目标减速）；稳定窗口通过 → `FINAL_CHECK`；复检通过 → `GRASP_READY`（`ready_rising_edge=1` 仅首次达成）。任何已授权后丢帧都会立即撤销许可（`TARGET_LOST_AFTER_READY`）。

在这些条件全部通过前，不要把 `STABLE`/`GRASP_READY` 连接到实际夹爪动作。
